# 想法收集 — v2.11.0: attach 权限透出

## 输入想法

> 处理 attach 权限检测:检测附加后实际拥有的权限并透出 AccessDenied(独立小版本)。

## 现状分析

- `deeptrace::attach(pid)` 先尝试 `PROCESS_ALL_ACCESS`,失败后降级到有限权限
  集合(QUERY_INFORMATION | VM_READ | VM_WRITE | VM_OPERATION | CREATE_THREAD |
  SUSPEND_RESUME),仍失败才返回 `AccessDenied`。
- CLI `ps attach` 成功时只打印 `OK`,用户不知道实际拿到多少权限;降权
  成功(能附加但权限受限)与全权限成功无法区分。
- `AccessDenied` 失败透出已存在(report_error),缺的是「成功时的权限信息」。

## 期望行为(与用户确认后的定稿)

1. `ps attach <pid>` 成功 → `OK (permissions: read|write|vm_operate|...)`:
   语义化权限名列表,人类与 AI 均可读,缺失位不显示。
2. 权限名用人类/AI 语义(不是 C 语言的 PROCESS_* 语义):
   `read`、`write`、`vm_operate`、`create_thread`、`suspend_resume`、
   `terminate`、`query`、`query_limited`、`dup_handle`、`create_process`、
   `set_quota`、`set_info`。
3. 权限来源 = attach 实际成功的 access 掩码(Session 记录),零额外探测、
   零副作用;`-p` 选哪个进程就检测哪个,无需检测全部进程。
4. 失败路径仍透出 AccessDenied(既有语义不变)。
5. 不新增独立探测 API(如 process_permissions(pid));仅查当前会话实际权限。

## 约束

- 纯 ASCII 输出;一次调用一个操作;退出码语义不变。
- 静态库零副作用:attach 不额外 OpenProcess 探测(直接用实际成功的掩码)。
- CLI 打印层做权限名格式化(纯函数,可单测)。
