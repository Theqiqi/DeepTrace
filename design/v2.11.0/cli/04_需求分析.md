# CLI - 需求分析(修改模式,功能,v2.11.0)

> 引用:v2.10.0/cli/04_需求分析.md。v2.11.0 为「attach 权限透出」改动:
> `ps attach` 成功后输出实际权限摘要(语义化名列表)。

## 1. 需求变更清单(改动点)

| # | 改动点 | 新增/修改/删除 | 影响命令组 |
|---|--------|----------------|------------|
| 1 | `ps attach <pid>` 成功时输出 `OK (permissions: read\|write\|...)` | 修改 | ps |
| 2 | 权限名语义化映射(read/write/vm_operate/...) | 新增 | 打印层 |
| 3 | 静态库 `session_permissions` 查询(契约返回) | 新增 | 静态库 |
| 4 | 版本号 2.11.0 | 修改 | 全局 |

## 2. 需求说明

### 2.1 attach 权限透出(修改功能点)

**动机**:attach 降权成功(能附加但权限受限)时,CLI 只打印 `OK`,用户无法
得知实际权限;配合 `-p` 检测所选进程的权限,排查句柄/权限问题。

**输入**:`ps attach <pid>`(无新参数)。

**处理**:
- attach 成功 → 调 `session_permissions` 取实际掩码 → 语义化名列表 →
  输出 `OK (permissions: read|write|vm_operate|...)`。
- attach 失败 → 既有 report_error(AccessDenied/NoSuchProcess)不变。

**输出示例**:
```text
$ deeptrace_cli ps attach 1234
OK (permissions: read|write|vm_operate|create_thread|suspend_resume|query)
```

**无交互约束**:一次调用一操作、执行完立即退出;输出纯 ASCII;退出码不变。

### 2.2 受影响既有功能点

- ps 其余动作(list/detach/info/suspend/resume/kill)不变;
- attach 失败语义(AccessDenied)不变;
- 静态库 attach/detach 行为不变(仅内部多记录一个掩码)。

## 3. 能力边界(声明支持 / 不支持)

- 支持:attach 成功后输出实际权限名列表;权限缺失位不显示。
- 不支持/错误:
  - 权限名映射为纯展示约定,静态库只返回掩码;
  - 不新增独立探测 API(不探测未 attach 进程);
  - attach 失败仍为既有错误路径(退出 1)。

## 4. 需求点设计

| 需求点 | 说明 |
|--------|------|
| R1 权限掩码查询 | attach 成功后调 session_permissions 取掩码 |
| R2 语义化名列表 | 掩码位 → read/write/vm_operate/... 名,`|` 连接,缺失位不显示 |
| R3 输出格式 | `OK (permissions: <list>)`,纯 ASCII |
| R4 错误不变 | attach 失败 AccessDenied 退出 1;session_permissions 异常 → 不掩盖 attach 结果 |
