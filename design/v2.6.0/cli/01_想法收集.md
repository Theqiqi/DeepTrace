# v2.6.0 想法收集:符号寻址(人造指针外部读值)

> 输入:用户问「给 mem read / watch add 等命令加符号寻址支持(如 mem read sunObjPtr),
> 配合人造指针外部读值更方便」。

## 1. 现状调查(结论)

v2.5.0 实现了脚本人造指针(符号引用):`script run` 后目标进程内存在按名分配的
槽位(如 `sunObjPtr`,8 字节),符号记录持久化在 per-PID 的 scripts.dat
(`SYM|<name>|<addr>|<owner>`)。CLI 侧:

| 能力 | 现状 |
|---|---|
| `script run <file>` 创建符号槽位 | ✅ 支持(script_alloc + 落盘记录) |
| `script status` 显示 符号→地址 | ✅ 支持(`alloc   sunObjPtr 0x...`) |
| `mem read 0x<地址>` 读槽位值 | ✅ 支持(但需先手抄地址) |
| **`mem read sunObjPtr` 直接按名读** | ❌ **不支持(解析器拒绝:invalid address)** |

缺的正是「把符号名当地址用」:目前用户拿到槽位地址的方式只有 `script status`
抄地址,再手动喂给 `mem read / watch add`。符号寻址就是去掉这步手抄。

## 2. 用户诉求拆解

- `mem read sunObjPtr` → 解析符号 `sunObjPtr` → 读其指向的 8 字节槽位值
  (人造指针模式:槽位里存的是对象指针,二次寻址时再 `mem read <ptr>`)。
- `watch add desc sunObjPtr qword` → 监视槽位值变化。
- 「等命令」:所有取地址参数的命令统一支持(disasm/watch/shellcode 同理)。

## 3. 方案要点

- **静态库新公共 API `script_symbol(name, &addr)`**:按名查当前 session 的符号
  记录,返回地址。语义与 `script_free` 的查找一致(load_script_symbols → 按名
  匹配),找不到 → NotFound,无 session → NotAttached,非法名 → InvalidArg。
- **CLI 解析器**:`address` 参数校验从「仅数字」放宽为「数字 或 ASCII 标识符
  形状」。仍拒绝含空白/符号字符的名字(如 `foo bar`、`0xZZ`)。
- **CLI 接口层**:`resolve_addr(s, &addr)` = 先试数字解析(strtoull),失败再调
  `deeptrace::script_symbol`。所有地址命令的 `to_addr` 调用点替换为
  `resolve_addr`,失败统一 `report_error`(NotFound → 退出 1)。
- **向后兼容**:纯数字 / `0x` 前缀地址行为完全不变;只有「数字解析不出的
  标识符形状」才走符号查找。

## 4. 边界与风险(记录)

- 符号名若为纯数字形状(如 `alloc(100,8)`)会被数字优先规则当作地址,不按符号
  处理;不鼓励,记录在案。
- `script check` 无 attach,不涉及符号寻址(地址命令本来就要求 -p)。
- 符号记录与脚本生命周期一致:disable 后 dealloc 释放,再按名寻址 → NotFound。
