# CLI - 需求分析(修改模式,增量,v2.6.0)

> 引用:v2.5.0/cli/04_需求分析.md。v2.6.0 为「符号寻址」功能增量:
> 地址型参数支持脚本符号名(人造指针槽位),CLI 自动解析为真实地址。

## 1. 需求变更清单

| # | 改动点 | 新增/修改/删除 | 影响命令组 |
|---|--------|----------------|------------|
| 1 | 地址型参数支持符号名(如 `mem read sunObjPtr 8`) | 新增 | mem / disasm / watch / shellcode |
| 2 | 静态库新公共 API `script_symbol(name, &addr)` 按名查符号记录 | 新增(静态库能力) | - |
| 3 | 解析顺序:数字优先,数字解析不出再按符号名查找 | 修改(地址参数语义) | 上表全部 |
| 4 | 错误语义:符号不存在 → NotFound(退出 1);名字形状非法 → 用法错误(退出 2) | 修改 | 上表全部 |

## 2. 需求说明

### 2.1 符号寻址(新增功能点)

**动机**:v2.5.0 人造指针在目标进程内创建了按名符号槽位(如 `sunObjPtr` 存对象
指针),但脚本外读取只能靠 `script status` 抄地址再手动传给 `mem read`。符号寻址
去掉手抄:地址参数直接写符号名。

**输入**:`mem read sunObjPtr 8` / `mem write sunObjPtr 1122334455667788` /
`watch add ptr sunObjPtr qword` / `disasm at code 5` / `shellcode run slotA` 等。

**处理**:解析器接受「数字地址 或 ASCII 标识符形状」;接口层先按数字解析,失败后
调用静态库 `script_symbol(name, &addr)` 取记录地址,再照常执行原命令动作。

**输出**:与对应数字地址命令完全一致(字节/值/监视条目),无新输出格式。

**无交互约束**:符号查找发生在 attach 之后(地址命令本就要求 `-p`);命令仍为
一次调用一操作、执行完立即退出。

**纯 ASCII 约束**:符号名本身是 ASCII 标识符,错误消息沿用 `Error: NotFound(...)`
等既有格式,不引入非 ASCII 输出。

### 2.2 受影响既有功能点(修改)

- `mem read/write/dump/readval`、`disasm at/range`、`watch add`、
  `shellcode injectat/run/free`:地址参数从「仅数字」放宽为「数字 或 符号名」。
- 数字地址行为完全不变(向后兼容);仅数字解析不出的标识符形状走符号查找。

## 3. 能力边界(声明支持 / 不支持)

- 支持:所有 address 类型参数按名引用已注册脚本符号;数字地址照旧。
- 不支持/错误:
  - 符号未注册(未 run / 已 disable)→ `NotFound` 退出 1。
  - 名字含空白/非标识符字符(如 `foo bar`、`0xZZ`)→ 用法错误退出 2。
  - 无 session(`-p` 缺失/失败)→ `NotAttached` 退出 1(既有语义)。
  - 符号名恰好为纯数字形状(如 `alloc(100,8)`)按数字地址解析,不按符号
    (数字优先,记录在案)。

## 4. 需求点设计

| 需求点 | 说明 |
|--------|------|
| R1 符号寻址 | address 参数支持符号名,解析为记录地址后执行原动作 |
| R2 数字优先 | 纯数字/0x 十六进制先按地址解析,行为不变 |
| R3 错误语义 | NotFound(1)/ 形状非法(2)/ NotAttached(1) |
| R4 能力边界声明 | 支持清单 + 不支持输入的错误,帮助文本不暗示未实现形式 |
