# deeptrace - 需求分析(v2.6.0,增量)

> 引用:v2.3.0/deeptrace 文档基线。v2.6.0 仅新增「符号按名查询」能力。

## 1. 需求

CLI 需要按符号名查脚本符号记录地址,用于地址参数符号寻址
(`mem read sunObjPtr` / `watch add ... sunObjPtr qword`)。

## 2. 现状与差距

- 已有:`script_alloc`(创建符号记录,输出地址)、`script_free`(按名释放)、
  `script_status`(全量列表)。记录格式 `SYM|<name>|<addr>|<owner>` 持久化于
  per-PID scripts.dat,内部结构 `ScriptSymbolRecord{name,address,owner}`。
- 差距:无按名查地址的只读 API。CLI 若用 script_status 全量扫描,输出模型
  (ScriptInfo) 与按名查找需求不匹配(需遍历所有脚本的 allocs);且符号可能属于
  (unowned),扫描逻辑脆弱。

## 3. 方案

新增公共 API `script_symbol(name, out_addr)`:
- session 检查(未 attach → NotAttached);
- 名字校验(复用 valid_symbol_name;空/非法 → InvalidArg;out 空 → InvalidArg);
- `load_script_symbols(pid)` 按名线性查找(记录量小,无需索引);
- 找到 → 写地址返回 Ok;未找到 → NotFound。
- 只读,不触碰记录文件写路径,无副作用。

## 4. 边界

- 重复符号不可能(script_alloc 防重),查找取首个匹配即可。
- 记录文件缺失/损坏:load_script_symbols 返回空 → NotFound(与 script_free 一致)。
