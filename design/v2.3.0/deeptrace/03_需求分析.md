# deeptrace - 需求分析(修改模式,v2.3.0)

> 引用:v2.2.0/deeptrace 既有需求文档。本版本聚焦脚本引擎能力需求。

## 1. 需求描述

CLI「脚本关键字引擎」(参考 CE AA)需要静态库支持 5 项能力:

1. **按大小分配 + 符号绑定(script_alloc)**:脚本 `alloc(name,size)` 在目标进程分配
   可执行内存并绑定符号名,供后续汇编写入、createThread、dealloc 引用;
2. **带 label 的汇编(asm_assemble_labels)**:脚本内 `jmp/call newmem` 等 label 引用,
   按符号地址正确计算 PC-relative 位移(现有 asm_assemble 逐行汇编,不支持跨行 label);
3. **任意地址建线程(thread_create_at)**:脚本 `createThread(name)` 在符号地址创建
   远程线程执行(现有 shellcode_run 限注入记录地址);
4. **hook 改写与恢复(hook_set/hook_clear)**:hook 目标地址改写为 `jmp newmem`,
   保存原始字节,disable 时恢复——仿 CE `"module"+offset:` 目标改写;
5. **脚本记录持久化(script_enable/disable/status)**:脚本启用状态按 PID 持久化,
   幂等判定(重复 enable/disable → Ok),跨 CLI 调用可见。

## 2. 需求点

| # | 需求点 | 验收 |
|---|--------|------|
| 1 | `script_alloc(name,size,addr*)`:分配+符号绑定,不写内容不建线程 | 集成测试:分配成功、符号表可查、重复同名 InvalidArg、dealloc 后消失 |
| 2 | `asm_assemble_labels(code,symbols,out)`:带 label 汇编,PC-relative 正确 | 集成测试:jmp 位移 = 目标−(下一条地址);未定义 label BadFormat;纯指令与 asm_assemble 一致 |
| 3 | `thread_create_at(addr,tid*)`:任意地址建线程 | 集成测试:TID 有效可 thread_list 查见;不要求注入记录 |
| 4 | `hook_set(addr,newmem,out)`/`hook_clear(addr)`:jmp 改写+保存/恢复原字节 | 集成测试:改写后 E9 跳转、clear 后字节与改写前一致、无记录 clear NotFound |
| 5 | `script_enable/disable/status`:脚本记录持久化+幂等 | 集成测试:重复 enable/disable → Ok;跨调用可见 |
| 6 | 分层与兼容:Service 组装(符号表/记录管理 + 基础设施);asm 扩展复用 Keystone | 代码审查:复用 RemoteAlloc/RemoteFree/CreateRemoteThreadEx/memory_read/write/asm_one;既有 API 不变 |

## 3. 无新三方依赖

纯 Windows API(VirtualAllocEx/VirtualFreeEx/CreateRemoteThread/ReadProcessMemory/
WriteProcessMemory)与既有 Keystone,经既有基础设施封装,不新增依赖。
