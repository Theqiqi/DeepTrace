## 3. 实现细化说明(相对交接记录的签名微调)

1. `script_alloc` / `hook_set` 增加 `owner` 参数(脚本路径):用于 script_status 按脚本
   过滤 hook/符号记录,避免多脚本状态输出错乱。CLI 调用时传脚本路径。
2. `asm_assemble_labels` 增加 `base_addr` 参数:PC-relative 位移需要代码写入地址;
   Keystone 的 rel32 fixup 存在系统偏差(+4,fixup 按字段偏移而非指令长度),故
   **jmp/call 到符号的编码由静态库自编码**(E9/E8 rel32,rel = target − (insn+5)),
   其他指令仍走 Keystone。内部 label(代码流内 `name:`)与外部符号均支持;
   非 jmp/call 指令引用符号 → BadFormat(能力边界)。
3. `script_free` 为 dealloc 关键字的必要补充(交接记录 M1 验收「dealloc 后符号消失」)。
4. 幂等语义:重复 enable → Ok 跳过;重复 disable → Ok 跳过;重复 hook_set →
   保留原始字节与 owner;重复 hook_clear → NotFound。

## 4. 异常与安全要求落实

- NotAttached / InvalidArg / NotFound / BadFormat / 读/写/分配失败路径全部实现并测试。
- 资源配对:script_alloc 保存失败回滚释放;hook_set 保存失败回滚写回原始字节;
  script_free 先删记录后释放(失败不留悬垂记录)。
- hook_clear 写失败保留记录可重试,目标不会半恢复。
- 无模拟数据/硬编码/伪造 API;全部使用真实底层能力(RemoteAlloc/RemoteFree/
  CreateRemoteThreadEx/ReadRemoteMemory/WriteRemoteMemory/Keystone)。
