# deeptrace - 职责和边界设计(修改模式,v2.3.0)

> 引用:v2.2.0/deeptrace/06_职责和边界设计.md 既有职责划分。本版本增量:

## 1. 新增模块职责

| 模块 | 职责 | 禁止项 |
|------|------|--------|
| Service: script | 脚本符号表管理(name→addr,按 PID 持久化);脚本启用记录(enable/disable/status,幂等) | 不直接调用 WinAPI;不执行汇编;不管理 hook 本身(只记状态) |
| Service: hook | hook 改写(jmp 编码+写入+nop 填充)、原始字节保存与恢复 | 不创建线程;不涉及脚本语法;不管理脚本启用记录 |
| Service: asm(扩展) | asm_assemble_labels:label 解析 + 符号地址重编码 | 不调用内存/线程基础设施;只做纯汇编(经 asm_one) |
| Service: thread(扩展) | thread_create_at:任意地址建线程 | 不涉及记录/符号;只做线程创建 |

## 2. 边界约束

- Service 各模块经基础设施(RemoteAlloc/RemoteFree/WriteRemoteMemory/CreateRemoteThreadEx/
  memory_read/memory_write/asm_one)与 store(记录持久化)组装,不跨层。
- hook_set 保存原始字节的时机 = 改写之前;hook_clear 必须先查记录(NotFound 否则)。
- script 模块只负责符号表与启用状态,alloc/dealloc 的实际内存操作由 script_alloc 调用
  RemoteAlloc/RemoteFree(符号表与内存操作在同一模块内组装,满足脚本 alloc/dealloc 配对)。
