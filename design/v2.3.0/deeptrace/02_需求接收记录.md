# deeptrace - 跨流程需求接收记录(design/v2.3.0/deeptrace/02_需求接收记录.md)

> 关联交接记录:design/v2.3.0/cli/09_静态库流程交接记录.md(CLI v2.3.0 发起)。

## 1. 接收清单(逐项)

### M1:按大小分配远程内存 + 符号绑定(script_alloc)

| 项 | 内容 |
|----|------|
| 缺失能力 | 按大小分配远程内存 + 符号绑定(脚本 alloc 关键字) |
| 期望公共 API | `Result script_alloc(const std::string& name, size_t size, uintptr_t* out_addr)` |
| 输入 | 符号名(ASCII)、分配大小(>0) |
| 输出 | *out_addr = 分配首地址;符号 name 登记脚本符号表(按 PID 持久化) |
| 异常要求 | 未 attach → NotAttached;空名/0 大小 → InvalidArg;符号重名 → InvalidArg;分配失败 → 分配错误(无残留) |
| 验收标准 | ①分配 PAGE_EXECUTE_READWRITE,不写内容不建线程;②符号表可查(name→addr);③重复 alloc 同名 → InvalidArg;④dealloc 后符号消失 |

### M2:带 label 的汇编(asm_assemble_labels)

| 项 | 内容 |
|----|------|
| 缺失能力 | 脚本内 jmp/call 引用 label 符号,PC-relative 正确解析 |
| 期望公共 API | `Result asm_assemble_labels(const std::string& code, const std::map<std::string,uintptr_t>& symbols, std::vector<uint8_t>& out, std::string* out_text)` |
| 输入 | 多行汇编文本(可含 label 引用)、符号表(name→addr) |
| 输出 | 机器码字节;jmp/call name 位移按符号地址计算(相对指令下一条地址) |
| 异常要求 | 未知指令 → BadFormat;引用未定义符号 → BadFormat(附符号名) |
| 验收标准 | ①`jmp newmem` = E9 <rel32>,rel32 = newmem_addr − (insn_addr + 5);②无符号引用输出与 asm_assemble 一致;③未定义 label → BadFormat |

### M3:对任意地址创建远程线程(thread_create_at)

| 项 | 内容 |
|----|------|
| 缺失能力 | 脚本 createThread 关键字:任意地址建线程执行 |
| 期望公共 API | `Result thread_create_at(uintptr_t addr, uint32_t* out_tid)` |
| 输入 | 目标地址(可执行内存) |
| 输出 | *out_tid = 新远程线程 TID |
| 异常要求 | 未 attach → NotAttached;地址 0 → InvalidArg;创建失败 → 错误 |
| 验收标准 | ①在 addr 创建新远程线程并执行;②TID 可被 thread_list 查见;③不要求 addr 在注入记录中 |

### M4:hook 改写与恢复(hook_set / hook_clear)

| 项 | 内容 |
|----|------|
| 缺失能力 | 目标地址改写为 jmp 到新内存 + 保存/恢复原始字节 |
| 期望公共 API | `Result hook_set(uintptr_t addr, uintptr_t newmem, HookInfo& out)` / `Result hook_clear(uintptr_t addr)` |
| 输入 | set:hook 目标地址 + 跳转目标(newmem);clear:目标地址 |
| 输出 | set:HookInfo{target, newmem, orig_bytes, size},改写 jmp+nop 填充,原始字节持久化;clear:恢复原始字节,删除记录 |
| 异常要求 | 未 attach → NotAttached;不可读/写 → 错误;覆盖长度不足(<5)→ InvalidArg;clear 无记录 → NotFound;恢复写失败 → 错误(记录保留) |
| 验收标准 | ①set 后目标首条指令为 E9 跳 newmem(disasm 验证);②orig_bytes 与改写前一致;③clear 后字节与改写前一致;④幂等:重复 set → 覆盖相同结果,重复 clear → NotFound |

### M5:脚本记录持久化(script_enable / script_disable / script_status)

| 项 | 内容 |
|----|------|
| 缺失能力 | 脚本启用状态跨调用持久化 + 幂等判定 |
| 期望公共 API | `Result script_enable(const std::string& path)` / `Result script_disable(const std::string& path)` / `Result script_status(std::vector<ScriptInfo>& out)` |
| 输入 | 脚本文件路径(脚本身份) |
| 输出 | enable:记录启用(pid+路径+关联 alloc/hook);disable:删除记录;status:列出已启用脚本与 hook |
| 异常要求 | 未 attach → NotAttached;重复 enable → Ok(幂等);未启用 disable → Ok(幂等) |
| 验收标准 | ①重复 enable 第二次 Ok(不重复分配);②重复 disable 第二次 Ok;③跨 CLI 调用可见 |

## 2. 约束确认

- 使用真实底层能力:VirtualAllocEx/VirtualFreeEx/CreateRemoteThread/WriteProcessMemory/
  ReadProcessMemory/Keystone(经既有基础设施 RemoteAlloc/RemoteFree/WriteRemoteMemory/
  CreateRemoteThreadEx/memory_read/memory_write/asm_one),禁止模拟/硬编码/伪造。
- 分层:Service 层组装(符号表/记录管理 + 基础设施调用);asm 扩展复用 Algorithm 与 Keystone 基础设施。
- 既有公共 API 全部保持兼容;注入记录/断点记录存储格式不变,脚本记录为**新记录类型**。
- 接收完成,进入需求分析。
