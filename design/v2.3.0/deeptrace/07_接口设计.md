# deeptrace - 接口设计(修改模式,v2.3.0)

> 引用:v2.2.0/deeptrace/07_接口设计.md 既有接口文档。本版本新增接口明细:

## 1. script_alloc

- 签名:`Result script_alloc(const std::string& name, size_t size, uintptr_t* out_addr)`
- 流程:
  1. 校验会话已 attach(NotAttached)、name 非空且 ASCII(InvalidArg)、size>0(InvalidArg);
  2. 查脚本符号表:name 已存在 → InvalidArg;
  3. RemoteAlloc(size, PAGE_EXECUTE_READWRITE) → 失败返回分配错误(无残留);
  4. 符号表登记 name→addr,持久化(scripts.dat);
  5. `*out_addr = addr`,返回 Ok。
- 异常:NotAttached / InvalidArg(空名、0 大小、符号重名)/ 分配失败。

## 2. asm_assemble_labels

- 签名:`Result asm_assemble_labels(const std::string& code, const std::map<std::string,uintptr_t>& symbols, std::vector<uint8_t>& out, std::string* out_text)`
- 流程(两遍):
  1. 按 `;`/换行拆分指令行,识别 `label:` 形式行(定义位置 = 当前累计长度偏移);
  2. 第一遍:逐条 asm_one 编码,记录每行长度与 label 定义偏移;
  3. 第二遍:含 label 引用的指令(操作数命中符号表)→ 用「符号地址 − 当前指令下一条
     地址」重编码(Keystone 支持绝对地址 → rel 编码);
  4. 引用未定义符号 / asm_one 失败 → BadFormat(附行号/符号名)。
- 异常:BadFormat(未知指令、未定义符号、语法错误)。

## 3. thread_create_at

- 签名:`Result thread_create_at(uintptr_t addr, uint32_t* out_tid)`
- 流程:校验 attach(NotAttached)、addr≠0(InvalidArg)→ CreateRemoteThreadEx(addr, 0)
  → *out_tid = tid → Ok。
- 异常:NotAttached / InvalidArg / 创建失败。

## 4. hook_set / hook_clear

- 签名:`Result hook_set(uintptr_t addr, uintptr_t newmem, HookInfo& out)`;
  `Result hook_clear(uintptr_t addr)`
- hook_set 流程:
  1. 校验 attach、addr≠0、newmem≠0;
  2. memory_read 读目标原始字节(暂按固定 5+ 字节读,后续按需 nop 填充;
     读失败 → 错误);
  3. 编码 `jmp newmem`(E9 rel32,rel32 = newmem − (addr+5)),memory_write 写入;
  4. 余下覆盖区写 nop(0x90)(覆盖长度默认 5,若目标指令长于 5 需脚本 `db` 补齐恢复,
     本版本覆盖长度 = 5 字节固定);
  5. hook 记录(addr→orig_bytes)持久化;out 填充。
- hook_clear 流程:查 hook 记录(NotFound)→ memory_write 写回 orig_bytes → 删记录。
- 异常:NotAttached / InvalidArg / 读/写失败 / NotFound(clear)。

## 5. script_enable / script_disable / script_status

- 签名:`Result script_enable(const std::string& path)`;
  `Result script_disable(const std::string& path)`;
  `Result script_status(std::vector<ScriptInfo>& out)`
- enable 流程:校验 attach → 脚本记录已存在(同 pid+path)→ Ok(幂等,跳过);
  否则登记(pid+path → enabled)→ 持久化。
- disable 流程:校验 attach → 记录不存在 → Ok(幂等,跳过);存在 → 删除 → 持久化。
- status 流程:读取脚本记录(含关联 hook 与符号)→ out 填充。
- 异常:NotAttached / 记录读写失败。

## 6. 公共数据结构

```cpp
struct HookInfo {
    uintptr_t target = 0;
    uintptr_t newmem = 0;
    std::vector<uint8_t> orig_bytes;
    size_t size = 0;
};
struct ScriptInfo {
    std::string path;
    std::string state;  // "enabled" | "disabled"
    std::vector<HookInfo> hooks;
    std::vector<std::pair<std::string, uintptr_t>> allocs;
};
```

## 7. 持久化格式(store 扩展)

- 脚本符号表:`scripts.dat` 行格式 `SYM|<name>|<addr>`(按 PID);
- hook 记录:`scripts.dat` 行格式 `HOOK|<target>|<newmem>|<orig_hex>|<size>`;
- 脚本启用记录:`scripts.dat` 行格式 `ENABLE|<path>|<hook_target>|<alloc_name>|<addr>`;
  幂等判定按 pid+path 匹配。
