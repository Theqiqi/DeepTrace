# CLI - 业务流程分析(修改模式,增量,v2.3.0)

> 引用:v2.2.0/cli/06_业务流程分析.md 既有业务流。本版本只重画受影响的新业务流(script 组),其余引用既有文档。

## 1. 业务流:script run(执行脚本 ENABLE,幂等)

```text
用户
  │  script run <file> -p <pid>
  ▼
[1] 解析脚本文件(AA 语法 → 步骤列表)
  │  语法错误 → Error: <msg> 退出 2
  ▼
[2] 校验 [ENABLE] 块存在
  │  无 ENABLE → Error: no [ENABLE] block 退出 2
  ▼
[3] 幂等检查:读取脚本记录(按 pid+脚本路径)
  │  已启用 → 输出 "already enabled" 退出 0
  ▼
[4] attach 目标进程(-p 指定;本次调用内自动 attach)
  │  失败 → Error 退出 1
  ▼
[5] 顺序执行 ENABLE 步骤
  │  ① 收集 label/label() 声明
  │  ② alloc(name,size):分配内存+符号绑定+记录
  │  ③ 裸汇编行:带 label 汇编 → 写入当前目标
  │  ④ db:原始字节写入当前目标
  │  ⑤ "module"+offset: 目标:读原字节 → jmp 改写 → 保存原始字节(hook)
  │  ⑥ createThread(name):创建远程线程执行
  │  ⑦ registersymbol:符号生效
  │  任一步失败 → 回滚已分配/已改写资源 → Error 退出 1
  ▼
[6] 输出执行摘要(地址/TID/hook 目标)退出 0
```

## 2. 业务流:script disable(执行脚本 DISABLE,幂等)

```text
用户
  │  script disable <file> -p <pid>
  ▼
[1] 解析脚本文件(语法错误 → 退出 2)
  ▼
[2] 校验 [DISABLE] 块存在(无 → 退出 2)
  ▼
[3] 幂等检查:脚本记录是否存在
  │  未启用 → 输出 "already disabled" 退出 0
  ▼
[4] attach 目标进程(失败 → 退出 1)
  ▼
[5] 顺序执行 DISABLE 步骤(逆序)
  │  ① unregistersymbol
  │  ② hook 目标:用保存的原始字节恢复 → 删除 hook 记录
  │  ③ dealloc(name):释放内存 → 删除分配记录
  │  恢复失败 → Error 退出 1(记录保留可重试)
  ▼
[6] 输出 "OK" + 摘要 退出 0
```

## 3. 业务流:script status

```text
用户
  │  script status -p <pid>
  ▼
[1] attach 目标进程(失败 → 退出 1)
  ▼
[2] 读取脚本记录(hook 目标/分配/脚本路径)
  ▼
[3] 输出纯 ASCII 状态表 退出 0(无记录 → 空表)
```

## 4. 幂等判定原理(用户确认方案)

- **无状态交互**:CLI 不维护跨调用会话;状态全部持久化在按 PID 的脚本记录文件中。
- **幂等规则**:执行开启命令任意次数,状态必为「开」;执行关闭任意次数,状态必为「关」。
  - enable 重复执行:记录已存在且目标有效 → 跳过(already enabled)。
  - disable 重复执行:记录不存在 → 跳过(already disabled)。
- **进程重启**:记录随进程校验(PID 校验),失效记录视为未启用(重新 enable)。

## 5. 一次调用一个操作约束

- `script run`/`script disable`/`script status` 均单条命令,自动 attach/detach,执行完立即退出。
- call 型脚本(无 hook,仅 alloc+createThread)若需完整生命周期:run 执行 ENABLE,disable 执行 DISABLE,两次独立调用。
