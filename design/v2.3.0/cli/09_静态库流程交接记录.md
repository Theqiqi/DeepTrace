## 2. 缺失能力清单(逐项:期望公共 API / 输入输出 / 异常要求 / 验收标准)

### M1:按大小分配远程内存 + 符号绑定(script_alloc)

- **期望公共 API**:`Result script_alloc(const std::string& name, size_t size, uintptr_t* out_addr);`
- **输入**:符号名(ASCII)、分配大小(>0)。
- **输出**:`*out_addr` = 分配首地址;符号 name 登记到**脚本符号表**(按 PID 持久化)。
- **异常要求**:未 attach → `NotAttached`;空名/0 大小 → `InvalidArg`;符号已存在 → `InvalidArg`;
  分配失败 → 分配错误(无残留)。
- **验收标准**:
  1. 分配 PAGE_EXECUTE_READWRITE 内存,不写内容、不建线程;
  2. 符号表可查(name → addr);重复 alloc 同名 → InvalidArg;
  3. dealloc 后符号消失。

### M2:带 label 的汇编(asm_assemble_labels)

- **期望公共 API**:`Result asm_assemble_labels(const std::string& code, const std::map<std::string,uintptr_t>& symbols, std::vector<uint8_t>& out, std::string* out_text);`
- **输入**:多行汇编文本(可含 label 引用)、符号表(name → 目标地址)。
- **输出**:机器码字节;`jmp name`/`call name` 的 PC-relative 位移按符号地址计算
  (相对指令下一条地址)。
- **异常要求**:未知指令 → `BadFormat`;引用未定义符号 → `BadFormat`(附符号名)。
- **验收标准**:
  1. `jmp newmem` 生成的字节 = E9 <rel32>,rel32 = newmem_addr − (insn_addr + 5);
  2. 无符号引用的纯指令与既有 asm_assemble 输出一致;
  3. 未定义 label → BadFormat。

### M3:对任意地址创建远程线程(thread_create_at)

- **期望公共 API**:`Result thread_create_at(uintptr_t addr, uint32_t* out_tid);`
- **输入**:目标地址(可执行内存)。
- **输出**:`*out_tid` = 新远程线程 TID。
- **异常要求**:未 attach → `NotAttached`;地址 0 → `InvalidArg`;创建失败 → 错误。
- **验收标准**:
  1. 在 addr 创建一条新远程线程并执行;
  2. TID 有效可被 thread_list 查见;
  3. 不要求 addr 在注入记录中(区别于 shellcode_run)。

### M4:hook 改写与恢复(hook_set / hook_clear)

- **期望公共 API**:
  `Result hook_set(uintptr_t addr, uintptr_t newmem, HookInfo& out);`
  `Result hook_clear(uintptr_t addr);`
- **输入**:hook 目标地址、跳转目标(newmem);恢复时仅目标地址。
- **输出**:
  - set:`HookInfo{target=addr, newmem=跳转目标, orig_bytes=被覆盖的原始字节, size}`;
    改写目标为 `jmp newmem`(+ nop 填充到覆盖长度);原始字节持久化(hook 记录)。
  - clear:用持久化的原始字节恢复目标地址;删除记录。
- **异常要求**:未 attach → `NotAttached`;addr 不可读/不可写 → 错误;
  覆盖长度不足(jmp 5 字节装不下)→ `InvalidArg`;clear 时无记录 → `NotFound`;
  恢复写失败 → 错误(记录保留可重试)。
- **验收标准**:
  1. set 后目标地址第一条指令为 E9 跳转到 newmem(可 disasm 验证);
  2. orig_bytes 与改写前读到的字节一致;
  3. clear 后目标地址字节与改写前完全一致(memory_read 验证);
  4. 幂等:重复 set 已 hook 的目标 → 跳过或覆盖为相同结果;重复 clear → NotFound。

### M5:脚本记录持久化(script_enable / script_disable / script_status)

- **期望公共 API**:
  `Result script_enable(const std::string& path);`
  `Result script_disable(const std::string& path);`
  `Result script_status(std::vector<ScriptInfo>& out);`
- **输入**:脚本文件路径(标识脚本身份)。
- **输出**:
  - enable:记录「脚本已启用」(PID + 路径 + 关联的 alloc 符号与 hook 目标);
  - disable:删除启用记录(须已先恢复 hook/释放内存);
  - status:列出当前目标进程所有已启用脚本与 hook。
- **异常要求**:未 attach → `NotAttached`;enable 重复 → 幂等(Ok,已启用);
  disable 未启用 → 幂等(Ok,已禁用)。
- **验收标准**:
  1. 重复 enable → 第二次 Ok(跳过执行,不重复分配);
  2. 重复 disable → 第二次 Ok(跳过执行);
  3. 跨 CLI 调用可见(不同进程实例读取同一记录)。

## 3. 约束与要求

- 静态库实现必须使用真实底层能力(内存分配/释放、远程线程创建、内存读写、Keystone
  汇编),禁止模拟数据、硬编码结果或伪造 API。
- 公共 API 签名须与上表一致;对外头文件 include/deeptrace.h 更新并同步文档。
- 复用既有基础设施:RemoteAlloc/RemoteFree/WriteRemoteMemory/CreateRemoteThreadEx/
  memory_read/memory_write/asm_one(Keystone)/store(记录存储)。
- 静态库流程完成后输出**静态库完成契约**,跳回 CLI 的「API 能力覆盖性匹配」阶段重新匹配。
