# CLI - 能力需求列表(修改模式,v2.3.0)

> 只回答「CLI 需要做什么」,不回答「用什么做」。聚焦改动点新增能力需求。

## 1. 改动点能力需求

| # | 能力需求 | 说明 |
|---|----------|------|
| 1 | 读文本文件(脚本 .aa) | CLI 标准库(std::ifstream) |
| 2 | AA 语法解析(块/关键字/标签/汇编行/db/模块偏移表达式) | CLI 或静态库(见能力匹配) |
| 3 | 幂等判定(按 PID+脚本路径记录「已启用/已禁用」) | 需记录持久化(仿 injects.dat) |
| 4 | **按大小分配远程内存 + 符号绑定(alloc name,size)** | **缺失 → 静态库流程** |
| 5 | **带 label 的汇编(脚本内 jmp/call 引用符号,PC-relative 解析)** | **缺失 → 静态库流程**(既有 asm_assemble 不支持 label) |
| 6 | **对任意地址创建远程线程执行一次(createThread name)** | **缺失 → 静态库流程**(既有 shellcode_run 限记录地址) |
| 7 | **hook 改写:目标地址改写为 jmp + 保存原始字节;恢复原始字节** | **缺失 → 静态库流程** |
| 8 | **脚本记录持久化(分配/hook 原始字节/启用状态,跨调用)** | **缺失 → 静态库流程**(新记录类型) |
| 9 | 汇编字节写入目标内存 / 原始字节读写 | 既有 memory_write/memory_read 覆盖 |
| 10 | 脚本状态输出格式 | CLI 打印层自实现 |

## 2. 能力覆盖判断

- 1:CLI 标准库自实现(与既有 hex_bytes 辅助同级)。
- 2:脚本解析器放 CLI(与 debug run 的 script::parse_file 同级,纯文本逻辑);语法语义正确性依赖静态库的带 label 汇编与 hook API。
- 9:既有 `memory_read`/`memory_write` 公共 API 覆盖。
- 4/5/6/7/8:静态库**无对应公共 API**:
  - `asm_assemble` 逐行汇编,不支持跨行 label 引用;
  - `shellcode_run` 仅限注入记录地址,不能对任意符号地址建线程;
  - 无 hook 改写/恢复 API;
  - 无脚本记录类型 → **缺失能力 5 项**,进入静态库流程。
