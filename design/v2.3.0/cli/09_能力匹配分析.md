# CLI - 静态库能力匹配(修改模式,v2.3.0)

## 1. 静态库存在性匹配

- 静态库存在:deeptrace(公共头 include/deeptrace.h,产物 out/lib/<配置>/deeptrace.lib,v2.2.0)。
- 继续「API 能力覆盖性匹配」。

## 2. API 能力覆盖性匹配

| CLI 能力需求 | 提供方 | 覆盖 |
|--------------|--------|------|
| 文本文件读取、脚本解析(AA 语法) | CLI(标准库自实现,与 debug run 的 script 解析同级) | 无需静态库 |
| 汇编字节写入 / 原始字节读写 | 既有 `memory_read`/`memory_write` | 覆盖 |
| **按大小分配远程内存 + 符号绑定(alloc name,size)** | 无对应 API(既有 shellcode_alloc 以字节为输入,无符号概念) | **缺失** |
| **带 label 的汇编(脚本内符号引用 jmp/call)** | 无对应 API(既有 asm_assemble 逐行,不支持 label) | **缺失** |
| **对任意地址创建远程线程执行(createThread name)** | 无对应 API(shellcode_run 限注入记录地址) | **缺失** |
| **hook 改写:目标地址 jmp + 保存/恢复原始字节** | 无对应 API | **缺失** |
| **脚本记录持久化(分配/hook 原始字节/启用状态)** | 无对应记录类型(既有 injects/breaks 记录语义不同) | **缺失** |

### 匹配结论

- 缺失能力 5 项(remote_alloc 带符号 / 带 label 汇编 / 任意地址建线程 / hook 改写恢复 / 脚本记录)。
- 其余能力全部覆盖;静态库流程被触发(见 09_静态库流程交接记录)。

## 3. 缺失能力分析(静态库需求)

> 详见 design/v2.3.0/deeptrace/ 静态库需求变更文档(与交接记录一并交付静态库流程)。

| 缺失能力 | 期望公共 API | 输入 → 输出 | 异常要求 | 验收标准 |
|----------|--------------|-------------|----------|----------|
| 按大小分配+符号 | `script_alloc(name,size,addr*)`(建议) | 名称+大小 → 分配地址,符号入脚本符号表 | NotAttached/InvalidArg/符号重名 | 可 mem 读到写入字节;dealloc 释放;符号表可查 |
| 带 label 汇编 | `asm_assemble_labels(code,symbols,out)`(建议) | 汇编文本+符号表(name→addr) → 字节(PC-relative 正确) | BadFormat(未定义 label) | `jmp name` 生成的位移 = name_addr - (insn_addr+len) |
| 任意地址建线程 | `thread_create_at(addr, out)`(建议) | 地址 → 新 TID | NotAttached/InvalidArg/建线程失败 | 线程在 addr 执行;TID 有效 |
| hook 改写/恢复 | `hook_set(addr,newmem,out)` / `hook_clear(addr,orig)`(建议) | 目标+新内存 → 改写字节+保存原字节;恢复 | NotAttached/不可写/长度不足 | 改写后目标跳转 newmem;恢复后与原始字节一致 |
| 脚本记录持久化 | `script_enable/disable/status`(建议) | PID+脚本路径 → 记录增删查 | 读写失败 | 幂等:重复 enable 跳过、重复 disable 跳过;跨调用可见 |

## 5. 静态库完成回退检查(契约已返回,v2.3.0)

> 回填自 design/v2.3.0/deeptrace/10_静态库完成契约.md。

| CLI 缺失能力 | 覆盖 API(真实签名) | 验证证据 |
|--------------|--------------------|----------|
| 按大小分配+符号(alloc name,size) | `script_alloc(name,size,owner,addr*)` | 集成测试 47/47(Debug/Release);公共头已含声明;产物存在 |
| 带 label 汇编(脚本内 jmp/call 引用) | `asm_assemble_labels(code,base_addr,symbols,out,text)` | 同上(反汇编验证跳转目标) |
| 任意地址建线程(createThread name) | `thread_create_at(addr,tid*)` | 同上 |
| hook 改写/恢复(目标 jmp+原始字节) | `hook_set(addr,newmem,owner,out)` / `hook_clear(addr)` | 同上(幂等+回滚) |
| 脚本记录持久化(幂等) | `script_enable(path)` / `script_disable(path)` / `script_status(out)` | 同上(幂等+所有权过滤) |
| dealloc 释放符号内存 | `script_free(name)` | 同上 |

- 匹配结论:5 项缺失能力(含补充的 script_free)全部由真实公共 API 覆盖
  (签名与契约一致,含 owner/base_addr 实现细化说明),无未覆盖能力 → 继续 CLI 接口调用设计。
- 静态库流程完成契约:公共头 ✓、API 列表 ✓、Debug/Release 产物 ✓、能力覆盖结果 ✓、
  测试结果 ✓、无未解决项。
- 注意:脚本的 alloc 关键字 → `script_alloc(name,size,owner,addr*)`;
  createThread → `thread_create_at`;hook 目标改写 → `hook_set`/`hook_clear`;
  dealloc → `script_free`;汇编块 → `asm_assemble_labels`(内部 label 自动解析)。
