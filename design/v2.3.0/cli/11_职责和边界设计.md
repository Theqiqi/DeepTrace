# CLI - 职责和边界设计(修改模式,增量,v2.3.0)

> 引用:v2.2.0/cli/11_职责和边界设计.md 既有职责划分。本版本增量:

## 1. 各层职责(沿用,新增约束)

| 层 | 职责 | 禁止项 |
|----|------|--------|
| 命令层 | script run/disable/status 命令登记与参数校验 | 不解析脚本内容;不调静态库 |
| 接口层 | 脚本文件读取、AA 语法解析、步骤执行(alloc/汇编/hook/线程/释放)、幂等检查、失败回滚 | 不直接调 WinAPI;只经静态库公共 API(deeptrace.h);不使用内部头文件 |
| 打印层 | script 输出格式化(步骤摘要、状态表) | 不调库;不解析脚本 |

## 2. 脚本解析器边界(接口层)

- 解析 AA 语法:`[ENABLE]`/`[DISABLE]` 块、`alloc(name,size)`、`label(name)`、
  `registersymbol(name)`、`unregistersymbol(name)`、`createThread(name)`、
  `dealloc(name)`、`db <hex>`、`name:` 标签、裸汇编行、`"module"+offset:` 目标行。
- 解析结果 = 结构化步骤(块 → 步骤序列),纯标准库实现。
- 汇编行本身**不解析**——整块文本交给 `asm_assemble_labels`(静态库,内部 label 解析)。

## 3. 执行器边界(接口层)

- ENABLE 执行顺序:label 收集 → alloc(script_alloc)→ 汇编块写入目标内存
  (asm_assemble_labels + memory_write)→ hook 目标改写(hook_set)→
  createThread(thread_create_at)→ 全部成功 → script_enable(幂等记录)。
- DISABLE 执行顺序:unregistersymbol → hook 恢复(hook_clear)→
  dealloc(script_free)→ script_disable。
- 幂等:run 前查 script_status 已启用 → 跳过;disable 前未启用 → 跳过。
- 失败回滚:ENABLE 中途失败 → 已 alloc 的 script_free、已 hook 的 hook_clear。

## 4. 无交互与纯 ASCII(沿用)

- 无阻塞等待(getchar/scanf/cin 不出现);脚本读取为文件 I/O;执行完立即退出。
- 全部输出纯 ASCII;错误 `Error:` 前缀。
