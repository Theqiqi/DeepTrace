# CLI - 功能点设计(修改模式,增量,v2.7.0)

> 引用:v2.6.0/cli/07_功能点设计.md。v2.7.0 仅修改「脚本 alloc」功能点的
> near 第三参数语义,其余功能点不变。

## 1. 修改功能点:alloc near 真实就近分配

### 1.1 描述

`alloc(name, size, near_expr)` 的第三参数(near)语义从「放置提示,不保证就近」
升级为**真实就近分配**:解析为锚点地址,在锚点 ±2GB 窗口内寻找满足 size 的
空闲区,优先贴近锚点,分配落点保证 RIP 相对 rel32 不超界。就近失败 → 报错,
不静默退化为任意分配。

### 1.2 执行链路(script run)

```
aa_parse_text ──► Step{kind=Alloc, name, size, text=near_expr}
   │  (语法校验:非法 near 表达式在此拒绝,check/run 一致)
   ▼
resolve_enable(enable, hook_addrs, ext_labels, near_anchors)
   │  对每个带 near 的 Alloc 步骤:
   │    "module"+offset → resolve_base(module) 校验加载 + anchor = base + offset
   │    裸地址          → parse_u64 得 anchor
   │  near_anchors[name] = anchor
   ▼
exec_enable(enable, ctx, hook_addrs, ext_labels, near_anchors)
   │  Phase 1 分配:
   │    有 anchor → deeptrace::script_alloc_near(name, size, anchor, path, &addr)
   │    无 anchor → deeptrace::script_alloc(name, size, path, &addr)  (不变)
   ▼
输出 "alloc <name> = 0x... (N bytes)"(与无 near 一致)
```

### 1.3 正常路径

```
alloc(newmem, 2048, "GameAssembly.dll"+0x7D5778)
  → parse: text = "\"GameAssembly.dll\"+0x7D5778"
  → resolve_enable: resolve_base(GameAssembly.dll) = 0x7FF6...0000
    anchor = 0x7FF6...0000 + 0x7D5778, near_anchors[newmem] = anchor
  → exec_enable: script_alloc_near(newmem, 2048, anchor, path, &addr)
    → 静态库在 anchor ±2GB 窗口找空闲区 → addr(距 anchor 最近可容纳区)
  → alloc newmem = 0x7FF6...(与 anchor 距离 < 2GB)
  → 后续 "GameAssembly.dll"+0x7D5778: jmp newmem 的 rel32 位移必不超界
```

### 1.4 错误路径

| 场景 | 层 | 输出 | 退出码 |
|------|----|------|--------|
| near 表达式语法非法 | 解析器(classify) | `script parse error ...: invalid alloc near ...` | 2 |
| 模块未加载 | resolve_enable | `Error: NotFound(<module>)` | 1 |
| 窗口内无足够空闲区 | script_alloc_near → Error | `Error: ...` | 1 |
| 就近分配成功但记录落盘失败 | script_alloc_near → Error(回滚释放) | `Error: ...` | 1 |

### 1.5 能力边界声明

- 支持:带 near 第三参数的 alloc 真实就近分配(±2GB 窗口、贴近锚点)。
- 不支持:就近失败时静默退化为任意分配(故意不做——声明 near 就真的 near)。
- 帮助文本:alloc 语法行补充说明 near 第三参数语义(就近 ±2GB 分配)。

## 2. 其余功能点

mem/disasm/watch/shellcode 等全部不变。
