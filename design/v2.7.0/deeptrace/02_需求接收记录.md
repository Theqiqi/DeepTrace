# deeptrace - 跨流程需求接收记录(v2.7.0)

> 来源:CLI v2.7.0 流程(alloc near 真实就近分配)。跳转目标:静态库流程
> 「跨流程需求接收」步骤。

## 1. 接收的缺失能力

CLI 脚本 alloc 第三参数(near)需真实就近分配(锚点 ±2GB 内,消除 RIP 相对
位移超界概率)。CLI 现有消费方式仅 `script_alloc`(裸 VirtualAllocEx 任意
选址)。缺「按锚点就近分配」的静态库能力,分配算法(VirtualQueryEx 窗口扫描)
属静态库内部实现,CLI 不得自行实现(须经公共 API),故进入静态库流程补充。

## 2. 期望公共 API

```
Result script_alloc_near(const std::string& name, size_t size, uintptr_t anchor,
                         const std::string& owner, uintptr_t* out_addr);
```

## 3. 输入输出

| 项 | 说明 |
|----|------|
| 输入 | name:符号名;size:字节数(>0);anchor:就近锚点地址;owner:脚本路径;out_addr:输出地址 |
| 输出 | Ok + 地址(落点在 anchor ±2GB 内,贴近锚点);Error(窗口内无空闲)/ NotAttached / InvalidArg |
| 异常要求 | 就近失败绝不静默回退任意分配;符号记录/落盘/回滚与 script_alloc 一致;失败时不得泄漏已分配内存 |
| 验收标准 | 真实 target 上以模块地址为锚点 alloc,返回地址与锚点距离 < 2GB;script_symbol 可查到同一地址;窗口无空闲(极端锚点)报错 |
