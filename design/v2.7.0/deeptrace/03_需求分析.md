# deeptrace - 需求分析(v2.7.0,增量)

> 引用:v2.6.0/deeptrace 文档基线。v2.7.0 新增「按锚点就近分配」能力。

## 1. 需求

CLI 脚本 alloc 第三参数(near)需真实就近分配:分配落点在锚点 ±2GB 窗口内、
优先贴近锚点,消除 RIP 相对 rel32 位移超界概率。CLI 需静态库提供
`script_alloc_near`(就近分配 + 符号记录)。

## 2. 现状与差距

- 已有:`RemoteAlloc`(裸 VirtualAllocEx,任意选址)、`script_alloc`(任意选址
  分配 + 符号记录 + 落盘 + 回滚)。
- 差距:无「按锚点就近分配」能力。v2.5.0 曾明确记录 near 仅作放置提示;
  实际分配可能与锚点相差数 GB,RIP 相对跳转运行时崩溃。

## 3. 方案

### 3.1 基础设施 `RemoteAllocNear`(infrastructure/memory)

两遍 VirtualQueryEx 扫描:

```
高窗 high = anchor + 0x7FFFFFFF(饱和到 UINTPTR_MAX)
低窗 low  = anchor - 0x7FFFFFFF(饱和到 0)
向上:pos = anchor;循环:
  VirtualQueryEx(pos) → mbi
  若 State==MEM_FREE:
    cand = align_up(max(base, anchor), 0x10000)   // 分配粒度对齐
    若 cand+size ≤ region_end 且 cand+size-1 ≤ high:
      VirtualAllocEx(cand) 成功 → 返回
    pos = region_end
  否则 pos = region_end;无进展则跳出
向下:pos = anchor;循环:
  VirtualQueryEx(pos) → mbi
  若 State==MEM_FREE:
    top = min(region_end, anchor)
    cand = align_down(top - size, 0x10000)
    若 cand ≥ max(base, low) 且 cand+size-1 ≥ low:
      VirtualAllocEx(cand) 成功 → 返回
    pos = base - 1(下溢则跳出)
  否则 pos = base - 1
窗口内无合适空闲区 → Result::Error
```

- MEM_FREE 区域的 RegionSize 即整个空闲区,单次查询即可覆盖大段地址;
  扫描步进为区域粒度,非页粒度,最坏几十次 VirtualQueryEx,开销可忽略。
- 优先向上(含锚点所在区 → 最近可能位置),再向下,满足「贴近锚点」。

### 3.2 公共 API `script_alloc_near`(service/script)

与 `script_alloc` 同构:session 检查 → 名字/size/out 校验 → 重复名检查 →
`RemoteAllocNear(handle, size, PAGE_EXECUTE_READWRITE, anchor, &remote)` →
记录 push + 落盘(失败回滚 RemoteFree + Error)→ 输出地址。

## 4. 边界

- 就近失败绝不回退:RemoteAllocNear 失败 → Error(与 script_alloc 的分配失败
  语义一致),调用方(CLI)报错退出。
- 32 位进程窗口(anchor ±2GB 饱和)覆盖全地址空间,语义自然成立。
- 符号记录格式/持久化路径不变,script_symbol/script_free 自动兼容新 API
  分配出的符号。
