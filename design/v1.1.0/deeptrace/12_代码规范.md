# deeptrace 静态库 - 代码规范

## 1. 通用规范

- 语言标准:C++20
- 命名:类型 PascalCase,函数/变量 camelCase,常量 SCREAMING_SNAKE,私有成员 m_ 前缀
- 头文件:每个 .h 有 include guard(`#pragma once`)
- 嵌套:不超过三重;错误后提前返回
- 异常:Service 层不向调用方抛异常;内部允许 try/catch 包裹系统调用边界
- 单一职责:一个函数只做一件事;文件过长(>500行)拆分

## 2. 分层规范

- 算法层:纯函数,无 I/O、无平台 API;头文件只依赖 domain/
- Infrastructure 层:基础能力最小封装,错误统一转换为 deeptrace::Result;按能力类型分子目录,同一能力跨平台以文件后缀区分(process_win32.cpp/process_linux.cpp)
- Service 层:组装,不内联算法;状态持久化在 Service 层
- utils 层:便捷门面,只转发调用不实现能力(按需)
- 公共头 deeptrace.h:只含标准 C++ 类型与 deeptrace 类型,禁止平台头

## 3. 错误处理

- 所有公共 API 返回 deeptrace::Result
- 失败必须设置错误原因(内部字符串),result_message 提供 ASCII 文本
- 指针输出参数必须判空

## 4. 跨平台

- 当前仅 Windows x64;源码文件使用 .cpp/.h
- 如未来扩展其它平台:同一能力的多平台实现以文件后缀区分文件名(process_win32.cpp / process_linux.cpp),不按平台建目录
- 禁止在公共头暴露平台宏

## 5. 测试规范

- 单元测试:算法层与 Infrastructure 纯能力(hex、AOB、解码/编码)边界/条件/分组
- 集成测试(Service 层):真实 target 进程串联多个 API
- target 程序:关闭 ASLR、已知地址放已知值、输出 PID 行 `PID: <number>`、banner 与变量对照表
