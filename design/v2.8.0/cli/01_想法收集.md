# v2.8.0 想法收集:mem write <symbol> 脚本外写人造指针值

> 输入:用户问「让脚本外也能直接写人造指针的值:mem write <symbol> <value>,
> 用于动态改指针目标」。

## 1. 现状调查(结论)

| 能力 | 现状 |
|---|---|
| `mem read sunObjPtr` 按符号读槽位 | ✅ v2.6.0 已支持(集成/e2e 已测) |
| `mem write sunObjPtr <value>` 按符号写槽位 | ✅ **v2.6.0 已支持但从未测试** |
| watch add / disasm / readval 按符号 | ✅ v2.6.0 已支持(已测) |

v2.6.0 的 `resolve_addr` 已接入 `mem write` 分支(cmd_memory.cpp write 动作
第一参数)。手动验证(真实进程):

```
alloc slotA 8 → mem write slotA 8877665544332211 hex → OK
             → mem read slotA → 88 77 66 55 44 33 22 11 ✓
             → mem write slotA 1122334455667788 dec → OK
             → mem read slotA → 4C 9C 8C DA C1 FC 03 00 (= 1122334455667788) ✓
             → mem write nosuch ... → Error: NotFound(nosuch) 退出 1 ✓
```

**缺的是测试覆盖**:v2.6.0 集成测试 SymbolAddressingMemReadWatchAdd 测了
read/readval/disasm/watch add,唯独漏了 mem write;e2e 符号寻址块同样没测;
单测 parser 无 mem write 符号形状用例。文档也无明确声明。

## 2. 用户诉求拆解

- `mem write sunObjPtr 0x7FF6...` → 解析符号 → 把 8 字节新目标指针写入槽位。
- 「动态改指针目标」:脚本内 `mov rax,[sunObjPtr]` 读到的即新目标;
  脚本外一行命令即可切换指针,无需重跑脚本。

## 3. 方案要点

- **零代码改动**:能力链路已通,本版本纯测试补强 + 文档声明。
- 单测:parser 断言 `mem write <symbol> <value> [fmt]` 解析通过(address 参数
  符号形状合法)。
- 集成:script run(aptr fixture)→ mem write slotA hex/dec → mem read 读回
  新值 → 未知符号 NotFound → disable 清理。
- e2e:符号寻址块补 mem write <符号> 动态改指针目标读回用例。

## 4. 边界与风险(记录)

- dec 格式固定 8 字节小端(与既有 mem write dec 一致);hex 按字节数任意。
- 符号生命周期:disable 后 NotFound(与 v2.6.0 一致)。
- 无行为变更,回归风险仅限测试新增;版本号按流程 +1 便于追溯。
