## 2. 需求说明

### 2.1 能力确认:mem write <symbol>(已实现,v2.6.0)

**动机**:用户需脚本外直接写人造指针槽位值,动态改指针目标
(`mem write sunObjPtr 0x7FF6...` → 脚本内 `mov rax,[sunObjPtr]` 读到新目标)。

**现状**:v2.6.0 符号寻址把 `resolve_addr`(数字优先 → script_symbol)接入
mem read/write/dump/readval、disasm、watch add、shellcode。mem write 分支
第一参数已走 resolve_addr,**能力已通**。真实进程手动验证(hex/dec 写入读回
一致、未知符号 NotFound)通过。

**缺口**:v2.6.0 集成测试/e2e 覆盖了 read/readval/disasm/watch add,唯独
mem write <symbol> 无用例;文档未声明。

**本版本动作**:补三类测试 + 帮助文本/文档声明。无生产代码改动。

### 2.2 受影响既有功能点(无修改)

- `mem write <address> <value> [format]`:语法、错误语义、值格式(hex 字节/
  dec 8 字节小端)全部不变;仅补符号形状用例。

## 3. 能力边界(声明支持 / 不支持)

- 支持:`mem write <symbol> <value> [hex|dec]` 写任意脚本符号指向的内存
  (人造指针槽位 / 代码缓冲区)。
- 不支持/错误:
  - 符号未注册 → NotFound 退出 1(v2.6.0 语义)。
  - 值格式非法(奇数 hex、非 hex 字符)→ InvalidArg 退出 2(既有)。
  - 无 session → NotAttached 退出 1(既有)。
  - dec 格式固定 8 字节小端;写小于 8 字节的槽位越界(与既有 dec 语义一致)。
