# 想法收集

## 输入(用户)

> 脚本有没有分配人造指针的功能,有没有必要添加?这好像就是 C 语言代码中的变量。
> (附 CE 经典人造指针脚本:`alloc(sunObjPtr,8)` + `registersymbol(sunObjPtr)` +
> hook 内 `mov [sunObjPtr],rax` 保存对象指针;DISABLE 里 `unregistersymbol`+`dealloc`)

## 调查结论

### 1. 现状:半有 —— 「分配」支持,「使用」不支持

| 人造指针需要的能力 | 现状 |
|---|---|
| alloc(name,size) 分配槽位 + 符号绑定 | 支持(script_alloc,per-PID 落盘记录) |
| registersymbol / unregistersymbol / dealloc | 支持 |
| script status 显示符号→地址 | 支持 |
| **mov [sym],reg / mov reg,sym(符号在普通指令中引用)** | **拒绝:BadFormat(符号引用仅限 jmp/call)** |

结论:用户示例脚本在 `mov [sunObjPtr],rax` 一行即失败,run/check 均报 BadFormat。

### 2. 「C 变量」类比成立

alloc 一个 8 字节槽位 + 名字绑定 + 生命周期管理,等价于在目标进程内声明
`uint64_t` 变量。CE 称为「人造指针」,是脚本保存对象指针/基址的最常用模式。

### 3. disable 释放机制确认(用户关心点)

- `[DISABLE]` 逆序执行 `dealloc(name)` → `script_free(name)` → 从
  `state_dir(pid)/scripts.dat`(格式 `SYM|<名字>|<地址>|<所属脚本>`)按**名字**找到
  地址 → VirtualFreeEx。与 CE「界面存符号表、按名释放」语义一致,名字即线索。
- 记录按目标 PID 落盘:CLI 进程重启后重新 attach 同一 PID,仍可按名释放。
- 性能:记录仅在 run/disable/status 时读写,脚本非持续执行,无性能问题。
- 边界:目标进程退出 → 远程内存随进程消亡(不泄漏),陈旧记录优雅返回 NotAttached。

### 4. Keystone 静默截断实测(决定性证据,决定编码方案)

用 `asm assemble` 纯本地汇编实测(2026-08-12,Debug 构建):

| 指令 | Keystone 实际编码 | 结论 |
|---|---|---|
| `mov [0x12345678],rax` | 48 A3 moffs64 完整 64 位 | 正确 |
| `mov [0x7FF612345678],rax` | 48 A3 moffs64 完整 64 位 | 正确 |
| `mov [0x7FF612345678],rcx` | 48 89 0C 25 <低 32 位> **静默截断** | 危险 |
| `mov [rip+0x1000],rax` | 48 89 05 disp32(RIP 相对) | 正确、紧凑 |
| `lea rax,[0x7FF612345678]` | 48 8D 04 25 <低 32 位> **静默截断** | 危险 |
| `mov rax,[0x7FF612345678]` | 48 A1 moffs64 完整 64 位 | 正确 |
| `mov rax,0x7FF612345678` | 48 B8 movabs imm64 完整 64 位 | 正确 |
| `mov ecx,0x7FF612345678` | B9 <低 32 位> **静默截断** | 危险 |
| `mov [rip+0x7FF600000000],rax` | 48 89 05 <0> **静默把位移截成 0** | 危险 |

结论:不能「把符号替换成地址丢给 Keystone」——非累加器内存操作数、超界 RIP 位移、
32 位立即数都会被**静默编错地址**,必须自行控制编码并校验。

### 5. 设计定案

- 静态库 `asm_assemble_labels` 扩展:
  - 内存操作数 `[sym]` → 重写 `[rip+disp32]`,两遍汇编(先占位定长,再算
    disp = sym - (insn_addr + len));位移超 int32 → BadFormat。
  - 立即数 `sym` → 替换地址字面量;Capstone 校验实际编码地址 == 符号地址,
    发现截断(32 位操作数装不下 64 位地址)→ BadFormat。
  - 复杂内存表达式(带寄存器基址等)→ 明确报错。
  - 流内 label 引用、jmp/call 引用行为不变(仍自编码 rel32)。
- CLI:exec_enable 符号表已含真实地址,编码层自动受益;check 预检用占位地址(低位),
  无距离问题,语法校验语义与 run 一致。
- 范围外:alloc near 真实就近分配(±2GB 距离限制作为边界记录)。
