# CLI - 需求分析(修改模式:需求变更文档,v2.5.0)

> 引用:v2.4.0/cli/04_需求分析.md 既有需求。本版本输出需求变更,逐条列出改动点。
> 输入:01_想法收集(人造指针需求 + Keystone 实测)+ 用户设计决策确认(完整实现符号引用)。

## 1. 已确认的设计决策(想法收集阶段的开放问题)

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 需求范围 | **完整实现**脚本汇编行的符号引用:alloc'd 符号/标签可被任意指令引用(内存操作数/立即数),不再限于 jmp/call |
| 2 | 编码策略 | 内存操作数 `[sym]` 重写为 RIP 相对 `[rip+disp32]`(两遍:占位定长 + 算位移);立即数替换地址字面量后用 Capstone 校验实际编码地址(防静默截断);装不下 → 显式 BadFormat |
| 3 | 静默截断 | **绝对禁止**:Keystone 实测会静默截断(高地址非累加器内存操作数/32 位立即数/超界 RIP 位移),必须校验,宁可报错不编错 |
| 4 | 释放机制 | 沿用既有 per-PID 落盘记录(scripts.dat):`[DISABLE] dealloc(name)` 按名查找释放,与 CE「名字为线索」一致;无性能问题;目标进程退出则内存随进程消亡 |
| 5 | 范围外 | alloc near 真实就近分配不做(±2GB RIP 相对距离限制作为能力边界记录) |
| 6 | 命令 | 不新增命令:语法/编码能力在既有 script run/check 内生效 |

## 2. 脚本语法(引用 v2.3.0,增量)

语法与关键字沿用 v2.3.0 定义(alloc/label/registersymbol/unregistersymbol/
createThread/dealloc/db/`[ENABLE]`/`[DISABLE]`/裸汇编行/`"module"+offset:`)。
**本版本增量**:裸汇编行可引用符号于任意指令——`mov [sym],reg`、`mov reg,[sym]`、
`mov reg,sym`、`lea reg,[sym]` 等;不再有「非 jmp/call 引用符号 → BadFormat」限制。

## 4. 无交互与纯 ASCII 约束复核

- 无阻塞输入等待;文件读取为 I/O;执行完立即退出;一次调用一个操作。
- 所有输出纯 ASCII;错误消息统一 `Error:` 前缀。
- 符号编码为纯本地汇编(静态库 asm_assemble_labels),无新增资源/句柄/线程操作。
- 新增需求点满足无交互与纯 ASCII 约束。

## 5. 能力边界声明(声明支持 / 不支持)

- **支持**:`mov [sym],reg` / `mov reg,[sym]` / `mov reg,sym` / `lea reg,[sym]`
  (sym 为 alloc'd 符号或脚本内标签);符号地址任意 64 位值;RIP 相对位移 ≤ int32;
  立即数目标为 64 位寄存器(rax 等,Keystone 自动 movabs imm64)。
- **不支持**(显式报错,绝不静默错编):
  - RIP 相对位移超 int32(符号距引用指令 > ±2GB)→ BadFormat。
  - 32 位操作数目标引用 64 位地址(`mov ecx,sym` 且 sym > 0xFFFFFFFF)→ BadFormat。
  - 复杂内存表达式引用符号(`[reg+sym]` / `[sym+reg]` 等)→ 明确报错。
  - 跨进程符号、模块未加载的地址表达式(与 v2.3.0 相同)。
- check 与 run 的检查差异不变:**check = 静态可判定问题(退出 2);run = 动态执行问题(退出 1)**;
  符号编码的距离/位数限制在 run 用真实地址时判定,check 用占位地址(低位)校验指令合法性。
