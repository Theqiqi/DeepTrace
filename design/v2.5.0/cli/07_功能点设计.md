# CLI - 功能点设计(修改模式,增量,v2.4.0)

> 引用:v2.3.0/cli/07_功能点设计.md 既有功能点。本版本新增 script check 功能点。

## 1. 功能点:script check(只检查不执行)

### 1.1 功能分析

- 输入:脚本文件路径(AA 风格)。**不 attach,不依赖 -p**。
- 检查步骤(纯本地,无目标副作用):
  1. 读文件(失败 → `Error: cannot read file: <path>` 退出 2)。
  2. `aa_parse_text` 语法解析(失败 → `Error: script parse error at line N: <msg>`
     退出 2;复用 run/disable 的解析器,保证语法判定一致)。
  3. **hook 块结构静态校验**(ENABLE 块):遍历步骤,`"module"+offset:` 目标之后
     必须紧跟 `jmp <label>`,且 label 已定义(脚本内 alloc 符号或 label 定义);
     否则 `Error: script check failed at line N: hook target must be followed by 'jmp <label>'`
     退出 2。hook 块内后续语句仅允许 CE 填充(nop N / db / 标签),与 run 规则一致。
  4. **汇编预检**:把 ENABLE 块的全部裸汇编行按「写入目标」分组(alloc 符号切换 /
     hook 目标切换处分组),每组以占位地址(base 0x1000 起)调用静态库
     `asm_assemble_labels(code, base, symbols, bytes)`——该 API 为纯本地汇编
     (v2.3.0 验证,无需 attach),Keystone 校验每条指令;未知指令/非法操作数 →
     `Error: script check failed at line N: BadFormat` 退出 2。
- 输出(全部通过):
  ```
  OK (N steps: X alloc, Y asm, Z hook, W createThread, V db)
  ```
  `N` = ENABLE 步骤总数;`X/Y/Z/W/V` = 各类步骤计数;纯 ASCII 单行。
- 错误路径:文件不可读 / 语法错误 / hook 结构错误 / 汇编失败,均为输入问题 → 退出 2。
- 退出码:0 通过 / 2 检查失败(输入/脚本问题)。无退出 1(check 不涉及业务执行)。

### 1.2 功能流程

```
cmd_script check:
  text = read_file(path)                  --fail--> Error: cannot read file + 2
  enable, disable = aa_parse_text(text)   --语法错--> Error: script parse error + 2
  # hook 块结构静态校验(ENABLE)
  for step in enable:                     --结构错--> Error: script check failed + 2
    check_hook_structure(step)
  # 汇编预检:按目标分组,占位地址汇编
  groups = group_asm_by_target(enable)    --分组:alloc/hook 边界
  for g in groups:                        --BadFormat--> Error + 2
    asm_assemble_labels(g, base, symbols) --fail--> Error + 2
  print "OK (N steps: ...)"
  return 0
```

## 2. 与既有功能点的关系

- check **不修改** run/disable/status 的行为;解析器 `aa_parse_text` 复用同一实现,
  保证「run 能过的脚本 check 必过、check 报错 run 必同样报错(解析层)」。
- 汇编预检的语义边界:能发现**指令级静态问题**(未知指令/非法操作数/未定义 hook
  label),不能发现**动态问题**(分配失败/写失败/模块未加载)——后者仍由 run 暴露,
  文档在 04_需求分析 §5 已声明。
