# CLI - 功能点设计(修改模式,v2.1.0)

> 引用:v2.0.0/cli/07_功能点设计.md。v2.1.0 改动:debug 功能点收敛为
> 「单一入口 debug run + 脚本步骤全量覆盖调试能力」;删除 debug 单命令功能点。

## 0. 背景:为什么收敛(实测结论)

v2.0.0 遗留 debug 单命令在无状态 CLI 下语义错误:
- `debug step` 两次执行 rip 相同(假单步,无调试会话);
- `debug break` 单独执行后目标内存残留 0xCC,无清理(污染目标,打在循环体上
  目标会因无人处理 INT3 崩溃);
- `debug registers/status` 读的是非暂停上下文/仅句柄状态(语义误导);
- `debug attach` 立即 attach 又 detach(无意义)。

动态调试强依赖**有状态调试会话**,无状态 CLI 只能暴露一个入口 `debug run`,
所有调试操作以脚本步骤执行(会话状态全程在本次调用内存中)。

## 1. 功能点:脚本解析与校验(script 模块,不变)

- 输入/解析/校验/错误路径与 v2.0.0 一致;op 表 = 调试能力全量入口。
- 校验 op 覆盖:break/clear/hbreak/hclear/guard/unguard/pause/resume/step/next/
  registers/register/status/continue + read/write/disasm/watch_*(全量表见 14_参数列表 §2)。

## 2. 功能点:会话执行(debug run,不变)

- 一次调用 = 一次完整调试会话:attach → debug_attach → 逐条步骤 → 清理 → detach。
- 步骤执行/continue 分支/清理/退出码均与 v2.0.0 一致(见 v2.0.0 07 §2)。

## 3. 删除功能点:debug 单命令(不再提供)

attach/detach/pause/resume/step/next/break/clear/hbreak/hclear/guard/unguard/
status/registers/register —— 从命令表删除;调用报 `unknown command`(exit 2)。
对应能力全部由脚本步骤提供(见 12_接口设计 §3 对照表)。

## 4. 既有命令(引用)

其余命令组功能流程不变,引用既有文档;`debug run` 不修改任何非 debug 命令行为。
