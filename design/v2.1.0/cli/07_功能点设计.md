# CLI - 功能点设计(修改模式)

> 引用:v1.0.0/cli/07_功能点设计.md。本版本新增 debug run 功能点,其余引用既有文档。

## 1. 功能点:脚本解析与校验(script 模块)

### 1.1 功能分析

- 输入:脚本文件文本(JSON 步骤数组,全部字段字符串值)。
- 解析:顶层数组 → 对象列表;每对象字段为 key=字符串值;支持 \" 与 \\ 转义。
- 校验(逐步骤):
  - op 必须存在于操作表;必填字段必须存在;字段值按类型校验
    (address/number/format/value-type/hex-bytes/index/ascii/tid)。
- 错误路径:文件不存在、JSON 语法错误(含行列号)、非数组、op 未知、字段缺失、
  字段值非法 → 统一 `Error: <消息>` + 退出 2。
- 能力边界:仅字符串值;不支持 JSON 注释/嵌套/数字/布尔值(明确报错)。

### 1.2 功能流程

```
read file → parse(json) → steps[] → validate each → ok/err
```

## 2. 功能点:会话执行(debug run)

### 2.1 功能分析

- 执行器按步骤表逐条执行;每步:打印 `[N] op [args]` 头 → 调用静态库公共 API
  (debug_*/memory_*/disasm_at/watch_*)→ 打印结果。
- continue 步骤调用 `deeptrace::debug_continue(timeout_ms, info)`:
  - hit && 软件断点 → `breakpoint hit at <addr> (rip = <rip>)`
  - hit && 其他异常 → `exception 0x<code> at <addr>`
  - exited → `process exited (code N)` → 停止脚本,退出 1
  - 超时 → `continue timeout (<ms> ms)`(步骤成功)
- 步骤失败(API 返回非 Ok)→ `Error: step N (<op>): <result_message>` → 停止,退出 1。
- 清理(成功/失败均执行):记录本次设置的 SW 断点地址与原始字节、HW 断点地址、
  guard 区域;依次清除(忽略清除失败?不,清除失败也报告但不改变退出码;文档化);
  `debug_detach()`。

### 2.2 功能流程

```
execute(steps):
  for i, step in steps:
    print header
    ok? → print result
    fail → print error; break
  cleanup(); debug_detach()
  return ok ? 0 : 1
```

### 2.3 退出码

- 0:全部步骤成功(含 continue 超时/命中)
- 1:会话级失败(attach/debug_attach 失败、步骤运行失败、continue 进程退出)
- 2:脚本文件/解析/校验错误(命令层之前拦截)
