## 2. continue 结果分支

- `Ok && hit && exception==0x80000003(EXCEPTION_BREAKPOINT)` → `breakpoint hit at <addr> (rip = <rip>)`
- `Ok && hit && 其他` → `exception 0x<code> at <addr>`
- `Ok && exited` → `process exited (code N)` → 停止脚本,退出 1
- `Result::Timeout` → `continue timeout (<ms> ms)` → 步骤成功
- `NotAttached/InvalidArg/Error` → 步骤失败路径

## 3. -p 自动 attach/detach 路径覆盖

- `-p <pid>` 由 executor 统一处理:attach → 执行命令 → detach(既有路径)。
- `debug run` 在其中:attach 后先 `debug_attach()`(进入调试模式),脚本执行,
  清理本次断点/守护页后 `debug_detach()`,再走 executor 统一 detach。
- 成对资源:attach/detach、debug_attach/debug_detach 在成功/失败路径均配对
  (见 15_异常设计 §3);配对正确性由测试阶段「副作用检查」验证(目标进程存活)。

## 4. 检查项

- 每个 pmem/静态库调用对应真实公共 API:是(上表逐条映射,含全部调试 API)。
- 调试能力无一遗漏:原 debug 单命令能力 100% 可由脚本步骤表达(见 12_接口设计 §3 对照)。
- 删除路径无残留:debug 单命令不再被 CLI 接受,无假调用/无重复实现。
