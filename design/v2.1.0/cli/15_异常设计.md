# CLI - 异常设计(修改模式,v2.1.0)

> 引用:v2.0.0/cli/15_异常设计.md。v2.1.0 改动:debug 单命令错误路径删除,
> 新增「调试操作必须走 debug run」的用法错误;其余错误路径不变。

## 1. 错误消息格式(沿用)

统一 `Error: <消息>` 前缀,纯 ASCII,输出到 stderr。

## 2. debug 相关错误路径与退出码

| 场景 | 退出码 | 消息示例 |
|------|--------|----------|
| 直接调用已删除的 debug 单命令(`debug step`/`debug break` 等) | 2 | `Error: unknown command: 'step'`(引导:帮助文本仅列 debug run) |
| 脚本文件不存在/不可读 | 2 | `Error: cannot open script file: demo.json` |
| JSON 语法错误 | 2 | `Error: script parse error at line 3 col 5: expected ']'` |
| 顶层非数组 / 步骤非对象 / 字段非字符串 | 2 | `Error: script parse error at line 2 col 1: top-level must be an array` |
| op 未知 | 2 | `Error: step 2: unknown op 'foo'` |
| 必填字段缺失 | 2 | `Error: step 2 (break): missing field 'addr'` |
| 字段值非法 | 2 | `Error: step 2 (break): invalid addr 'xyz'` |
| attach/-p 失败 | 1 | `Error: attach: NoSuchProcess` |
| debug_attach 失败 | 1 | `Error: debug attach: AccessDenied` |
| 步骤执行失败(API 非 Ok) | 1 | `Error: step 3 (step): NotAttached` |
| continue 进程退出 | 1 | `process exited (code 5)` → 退出 1 |
| continue 命中/异常/超时 | 0 | `breakpoint hit at 0x... (rip = 0x...)` 等(正常结果) |

## 3. 会话清理(成功/失败均执行)

- 记录本次会话设置的 SW 断点(addr+orig)、HW 断点(addr)、guard 区域(addr+size);
- 依次清除(清理失败打印警告但不改变退出码);最后 `debug_detach()`。
- detach 失败 → 打印警告;退出码以主流程结果为准。

## 4. 异常边界

- 无阻塞等待:continue 步骤超时即返回(不会无限等待)。
- 进程退出后其余步骤:执行器检测 exited 后停止脚本,不再执行后续步骤。
- debug 单命令不再可用:任何调试操作必须通过 `debug run` 脚本执行,
  从入口上杜绝「假单步/断点残留/语义误导」类错误。
