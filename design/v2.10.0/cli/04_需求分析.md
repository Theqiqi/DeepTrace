# CLI - 需求分析(修改模式,功能,v2.10.0)

> 引用:v2.9.0/cli/04_需求分析.md。v2.10.0 为「mem batch 输出导出」改动:
> `mem batch <read|write> <file.json> [--format table|csv|json] [--out <file>]`,
> 让批量结果可喂给其他工具或 AI。

## 1. 需求变更清单(改动点)

| # | 改动点 | 新增/修改/删除 | 影响命令组 |
|---|--------|----------------|------------|
| 1 | `mem batch` 新增可选参数 `--format table\|csv\|json`(缺省 table) | 修改 | mem batch |
| 2 | `mem batch` 新增可选参数 `--out <file>`(落盘,缺省 stdout) | 修改 | mem batch |

## 2. 需求说明

### 2.1 批量结果导出(新增功能点)

**动机**:batch read 输出固定表格,脚本/jq/AI 直接消费需结构化格式;batch
write 逐条 `OK <name>` 同样不可机器解析。

**输入**:`mem batch <read|write> <file.json> [--format table|csv|json]
[--out <file>]`;`--format` 缺省 `table`(输出与 v2.9.0 完全一致,向后兼容);
`--out` 指定导出文件(否则写 stdout)。

**处理**:
- read:逐项定位 → 最终地址 → 按 type 读值;每行产出 name/address/value/status/error。
- write:逐项定位 → 写 value;每行产出 name/address/status/error(value 空)。
- 格式化在打印层(纯函数,可单测):table 保持现状;CSV 固定列
  `name,address,value,status,error`(RFC4180 引号转义);JSON 对象数组(字符串转义)。
- `--out` 落盘在接口层(新增 write_text_file),失败 → 退出 1。

**输出示例**:
```text
# table(现状,失败行 value 显示 error)
NAME                     ADDRESS            VALUE
player_hp                0x00007FF62A1B2100 0x3E8
bad_item                 0x0000000000000000 error

# csv
name,address,value,status,error
player_hp,0x00007FF62A1B2100,0x3E8,ok,
bad_item,0x0000000000000000,,error,NotFound(bad_item)

# json
[{"name":"player_hp","address":"0x00007FF62A1B2100","value":"0x3E8","status":"ok","error":""},
 {"name":"bad_item","address":"0x0000000000000000","value":"","status":"error","error":"NotFound(bad_item)"}]
```

**无交互约束**:一次调用一操作、执行完立即退出;输出纯 ASCII;退出码语义
不变(0 成功/1 业务错误/2 用法错误)。

### 2.2 受影响既有功能点

- batch JSON 定位器解析、链遍历、类型系统、process 校验完全不变(引用
  v2.9.0);仅输出层增加格式化能力与两个可选参数。
- `--out` 复用 convert 的 out-flag 解析机制,行为一致。

## 3. 能力边界(声明支持 / 不支持)

- 支持:`--format table|csv|json`;`--out <file>`(与 --format 组合);
  read/write 两模式导出;status/error 字段;CSV 引号转义;JSON 字符串转义。
- 不支持/错误:
  - `--format` 取值非法 / 缺值 → 用法错误退出 2。
  - `--out` 缺值 → 用法错误退出 2(与 convert 一致)。
  - `--out` 写文件失败(路径不可写等) → `Error: cannot write file: <path>`
    退出 1。
- 表格格式失败行仍显示 `error` 字符串(与 v2.9.0 一致),CSV/JSON 中为
  status=error + error 字段。

## 4. 需求点设计

| 需求点 | 说明 |
|--------|------|
| R1 导出参数 | --format(table/csv/json,缺省 table)+ --out(落盘,缺省 stdout) |
| R2 read 导出 | 每行 name/address/value/status/error |
| R3 write 导出 | 每行 name/address/status/error(value 空) |
| R4 CSV 格式 | 固定 5 列;RFC4180 引号转义(逗号/引号/换行) |
| R5 JSON 格式 | 对象数组;字符串转义;address 保持 0x hex 字符串 |
| R6 错误语义 | --format/--out 用法错误(2);落盘失败(1);batch 业务失败(1)不变 |
