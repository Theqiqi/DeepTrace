# pmem 静态库 - 技术选型

## 1. 技术选型

| 项 | 选择 |
|----|------|
| 程序类型 | 静态库(非 exe) |
| 语言 | C++20 |
| 平台 | Windows x64 |
| 构建 | CMake(CMakeLists.txt + CMakePresets.json) |
| 生成器 | Ninja(仅 Ninja) |
| 工具链 | MSVC(cl.exe,经 vcvars64 提供) |
| 包管理 | vcpkg manifest(已检测到 VS 自带 vcpkg.exe 与 VCPKG_ROOT) |
| 三方依赖 | gtest(仅测试;经 vcpkg manifest 管理) |
| 汇编能力 | Keystone 0.9.2(源码自建,位于 third_party/keystone;中大型库手动下载优先,见第 5 节决策理由) |
| 运行时链接 | Debug=/MDd(MultiThreadedDebugDLL,x64-windows);Release=/MT(MultiThreaded,x64-windows-static) |
| 输出目录 | out/bin/<配置>、out/lib/<配置>(由 CMakePresets cacheVariables 声明) |
| 命名 | pmem(进程内存操作类) |

## 2. 目录约定

```
pmem/
├── CMakeLists.txt
├── CMakePresets.json
├── vcpkg.json
├── include/pmem.h
├── src/{domain,algorithm,infrastructure,service,utils}/ + CMakeLists.txt
├── test/{target,unit,integration}/ + 各 CMakeLists.txt
├── script/{build_debug,build_release}.bat + {build_debug,build_release}_wsl.sh
└── out/
```

- src/infrastructure/ 按能力类型分子目录(process/memory/module/thread/debug/inject/disassembly/logging 等,按项目需要确定)
- 同一能力跨平台时以文件后缀区分文件名(process_win32.cpp / process_linux.cpp),不按平台建目录
- utils 按需创建,只做便捷门面不实现能力

## 4. 静态库交付约定

- 产物:pmem/out/lib/<配置>/pmem.lib + pmem/include/pmem.h
- 无 install/ 目录、无安装脚本(无其他依赖)
- CLI 经 find_library 直接引用 ../pmem/out/lib/<配置>/pmem.lib
- 汇编能力依赖 keystone(源码自建):静态库不合并依赖,消费方(CLI)需额外链接 keystone.lib(pmem/out/build/<配置>/third_party/keystone/lib/keystone.lib),见 cli/src/CMakeLists.txt 的 find_library(KEYSTONE_LIB)

## 5. 汇编能力选型说明(Keystone)

背景:自研编码器(asmenc)为手写子集实现,仅覆盖常见整数指令(缺 SSE/AVX/字符串指令/内存操作数等),曾导致 `asm assemble "add rax,0"` 等报 BadFormat 的汇编失效 bug。

选型:Keystone 0.9.2(与 Capstone 同作者,Keystone=汇编、Capstone=反汇编),x86/x64 汇编完整。

决策理由(依据流程文件包管理选型原则:小型库 vcpkg 优先,中大型库手动下载优先,哪个快用哪个):

- vcpkg 官方 registry 有 keystone port(0.9.2),但其 portfile 默认全架构构建(LLVM_TARGETS_TO_BUILD 未裁剪),全量 LLVM 编译需数十分钟;keystone 属中大型库,手动下载源码裁剪 X86 后端编译快得多 → 选择源码自建
- 接入方式(源码自建,参照 capstone 的 sandbox 验证结论):源码放入 pmem/third_party/keystone(来自 keystone-engine/keystone tag 0.9.2)
- **绕开 keystone 根 CMakeLists**(其会构建 kstool/suite/fuzz 等无关目标并强制 /MT),直接在 pmem/CMakeLists.txt 里 `add_subdirectory(third_party/keystone/llvm)` 集成其 llvm 子目录
- `LLVM_TARGETS_TO_BUILD=X86` 裁剪编译量(仅 x86/x64 后端)
- `PYTHON_EXECUTABLE` 指向 third_party/python 嵌入式 python(Windows 侧无 python;llvm-build 生成 LLVMBuild 数据需要)
- 老 LLVM 3.9 代码与 C++20 不兼容(std::unary_function 等在 C++17 移除),keystone 目标强制 `CXX_STANDARD 14`
- 语法:Intel(默认),x64 模式(KS_MODE_64)

约束:

- 基础设施层只暴露 asm_one 单指令接口(接口不变),内部实现切换为 keystone;Service/公共 API/CLI 均无需改动
- keystone 不支持的指令返回失败 → 上层仍为 BadFormat,语义不变
- 静态库仍为静态链接:keystone 编译为静态库并入 pmem.lib,不产生额外 DLL 依赖
