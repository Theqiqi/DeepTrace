# pmem 静态库 - 职责和边界设计

## 1. 各层职责

### Domain 层(src/domain)
- 定义全部数据结构与枚举
- 禁止任何逻辑(仅类型)

### 算法层(src/algorithm)
- 纯计算:hex 编解码、AOB 匹配、数值格式化
- 禁止包含平台 API、禁止 I/O、禁止进程读写
- 只依赖 Domain 层类型
- 输入输出均为内存数据(字节流/字符串)
- 说明:x64 解码/编码属机器级能力,归入 Infrastructure/disassembly(仍为纯函数,同样禁止 I/O)

### Infrastructure 层(src/infrastructure)
- 基础能力最小封装,按能力类型分子目录(进程/内存/模块/线程/调试/注入/反汇编/日志/线程池/网络/数据库等,按项目需要确定)
- 平台相关能力封装真实平台机制(WinAPI/Linux 机制);纯能力(如 x64 解码/编码)同样归本层按能力分类
- 不组装业务流程,不持久化,不维护跨多次调用的会话状态(会话归 Service 层)
- 每个能力可独立验证,错误统一转换为 pmem::Result
- 不按平台建目录:同一能力的多平台实现以文件后缀区分文件名(process_win32.cpp / process_linux.cpp)

### Service 层(src/service)
- 组装:数据结构 + 算法 + Infrastructure 能力,实现公共 API
- 会话管理(附加的 pid/句柄)
- 断点/watch/注入/壳码状态持久化(状态文件)
- 错误码语义化(result_message)
- 禁止直接调用平台机制(必须经 Infrastructure)

### utils 层(src/utils)(按需)
- 便捷门面:仅封装对 Infrastructure 能力的方便调用(如 log.h 转发到 Logger)
- 不实现任何能力、不含业务逻辑

## 2. 禁止项

| 层 | 禁止 |
|----|------|
| Domain 层 | 逻辑、I/O |
| 算法层 | 平台 API、I/O、进程读写、非纯函数 |
| Infrastructure 层 | 业务流程、持久化、跨多次调用状态 |
| Service 层 | 直接平台 API、业务算法内联(应调算法层) |
| utils 层 | 实现能力、业务逻辑 |
| 公共头 | 暴露平台头类型 |

## 3. 依赖方向

```
Service → 算法层 + Infrastructure + Domain(+ utils 便捷调用)
Infrastructure → Domain + 平台机制
算法层 → Domain
Domain → 无
utils → Infrastructure(仅便捷封装,不实现能力)
```
禁止跨层:算法层不得调用 Infrastructure/Service;Service 不得绕开 Infrastructure 直接调用平台机制;utils 不得包含业务逻辑。

## 4. 状态持久化约定

- 状态文件目录:%TEMP%/pmem_<pid>/ 下
  - breakpoints.dat(软件/硬件断点原字节)
  - watch.dat(监视条目)
  - inject.dat(注入 DLL/壳码记录)
- 持久化由 Service 层实现,算法层与 Infrastructure 层不得参与
