# v2.9.0 想法收集:批量定位器 JSON 配置(mem batch read/write)

> 输入:用户问「读取指针链需要吗?现在有没有读取地址+偏移的入口?读取模块地址+
> 地址+偏移的入口或者组合?加指针链搜索功能还是用现有功能组合替代找指针链?
> 结构化数据存储地址与偏移+支持模块解析地址」。

## 1. 现状调查(结论)

| 需求 | 现有能力 | 缺口 |
|------|----------|------|
| 地址+偏移入口 | ❌ address 参数只接受纯数字或符号名(v2.6.0),不支持表达式 | 无表达式语法 |
| 模块地址解析 | ✅ module base / resolve base(输出基址) | 结果需手抄 |
| 模块+偏移一次性入口 | ❌ 脚本里 `"module"+off` 语法是脚本专用 | 无 |
| 读指针(8 字节) | ✅ mem read <addr> 8 / readval qword | 中间指针需手抄 |
| 一次性指针链解析 | ❌ `[[module+off]+off]` 式读链不存在 | **核心缺口** |

当前读指针链的手动组合:`module base` 抄基址 → `mem read 基址+off 8` 抄指针
→ 逐层手抄,3 层链抄 3 次,极易错。

## 2. 多轮讨论定稿(用户决策记录)

1. **不做指针链专用命令**:用户明确「cli无需添加ptr命令,之前的读写基本功能在,
   复杂的做成配置来交互」。
2. **JSON 配置驱动**:「指针链配合json文件,json文件不止指针链还能读取符号+偏移
   还能读取地址,模块名写在json中」。
3. **统一模型**:「地址列表 vs 指针链」不是二选一——统一为「定位器」:单级=
   地址/符号+偏移/模块+偏移,多级=指针链。一个格式通吃,批量读顺带支持。
4. **读写语义**:链解析的产物是最终地址;读 = 地址+可选读值(输出两列),
   写 = 最终地址写 value(写的是值不是地址——用户指出)。
5. **命令命名**(用户选定):`mem batch read` / `mem batch write`。
6. **JSON 结构**(用户定稿):顶层 version/process/values 对象,每项
   base/offsets/type,扁平清晰「对任何人类和 agent 都友好」,避免多重嵌套。
   C++ 抽象即用户给出的 `struct OffsetPath`。
7. **type 语义化**(用户观点):不用 int8/int16 这类程序员视角名,
   用 byte/float/double/string/bytes 语义名。
8. **输出**:表格式(打印比落表格文件清晰)。
9. **文件即存储**:用户维护 .json,CLI 只执行。

## 3. 方案要点

- 新模块 `batch`(interface/batch.h/cpp,仿 script 模块):极简 JSON 解析器
  (顶层对象 + 字符串值 + 裸数字 token + offsets 字符串数组),解析为
  `OffsetPath` 列表并校验。
- `mem batch read <file>`:解析 → process 校验 → 逐项解析定位器(module→
  resolve_base+base / symbol→script_symbol / base→绝对地址)→ 链遍历
  (每级 memory_read 8 字节读指针 + 偏移)→ 按 type 读值 → 表格打印。
- `mem batch write <file>`:同一定位器解析 + 写 value(typed_bytes 复用)。
- 零静态库改动:resolve_base / script_symbol / memory_read / memory_write
  均为现有公共 API。

## 4. 边界与风险(记录)

- type 的 string 读:ASCII,遇 NUL 停,上限 256;bytes 读 count 字节 hex。
- 写 string:value + '\0'(读回完整);写 bytes:value 为 hex 串。
- process 校验:可选;存在时 attach 后比对进程名,不匹配退出 1。
- 指针链中间读失败(野指针)→ ReadFault 退出 1,该条目报错不中断其余条目
  (或中断?实现期决定——倾向逐条报错继续,最后汇总退出码)。
- 后续优化项(记录,不在本期):ps attach/detach 冗余 + attach 后权限检测
  (用户:检测返回附加后实际拥有的权限才是正解;OpenProcess 降权探测需谨慎
  设计避免副作用,独立小版本 v2.10 处理)。
