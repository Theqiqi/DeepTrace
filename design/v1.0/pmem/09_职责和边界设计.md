# pmem 静态库 - 职责和边界设计

## 1. 各层职责

### 数据层(src/data)
- 定义全部数据结构与枚举
- 禁止任何逻辑(仅类型)

### 算法层(src/algorithm)
- 纯计算:hex 编解码、AOB 匹配、x64 解码/编码、数值格式化
- 禁止包含 WinAPI、禁止 I/O、禁止进程读写
- 只依赖数据层类型
- 输入输出均为内存数据(字节流/字符串)

### 原子化层(src/atomic)
- WinAPI 最小封装:句柄打开、快照枚举、单次读写、上下文操作
- 不组装业务流程,不持久化
- 只做"一次系统调用"的封装 + 错误码转换

### 接口层(src/api)
- 组装:数据结构 + 算法 + 原子化,实现公共 API
- 会话管理(附加的 pid/句柄)
- 断点/watch/注入/壳码状态持久化(状态文件)
- 错误码语义化(result_message)
- 禁止直接调用 WinAPI(必须经原子化层)

## 2. 禁止项

| 层 | 禁止 |
|----|------|
| 数据层 | 逻辑、I/O |
| 算法层 | WinAPI、I/O、进程读写、非纯函数 |
| 原子化层 | 业务流程、持久化、跨多次调用状态 |
| 接口层 | 直接 WinAPI、业务算法内联(应调算法层) |
| 公共头 | 暴露 windows.h 类型 |

## 3. 依赖方向

```
接口层 → 算法层 + 原子化层 + 数据层
原子化层 → 数据层 + WinAPI
算法层 → 数据层
数据层 → 无
```
禁止跨层:算法层不得调用原子化层,接口层不得绕开原子化层直接调用 WinAPI。

## 4. 状态持久化约定

- 状态文件目录:%TEMP%/pmem_<pid>/ 下
  - breakpoints.dat(软件/硬件断点原字节)
  - watch.dat(监视条目)
  - inject.dat(注入 DLL/壳码记录)
- 持久化由接口层实现,算法层不得参与
