# CLI - 职责和边界设计

## 1. 各层职责与禁止项

### main
- 职责:初始化、调 CommandParser 解析、分发到 Executor、取退出码退出
- 禁止:执行业务逻辑、直接调用 pmem

### 命令解析层(command)
- 职责:解析全局选项(-p/-h/-v)、命令路由、参数校验、构造 CommandRequest
- 禁止:执行业务、调用 pmem、输出业务结果
- 允许:输出参数错误信息(打印层函数)

### 接口调用层(interface)
- 职责:根据 CommandRequest 调用 pmem 公共 API,组织返回结果
- 禁止:直接 WinAPI、自己实现 pmem 已有能力、格式化输出
- 允许:将 pmem 结果交给打印层

### 命令打印层(printing)
- 职责:纯格式化(进程表/区域表/模块表/寄存器表/hex dump/错误文本/帮助)
- 禁止:调用 pmem、依赖解析层与接口调用层、业务逻辑
- 所有输出纯 ASCII

## 2. 静态库边界

- CLI 只允许包含 pmem 公共头文件 `pmem.h`
- CLI 只允许调用 pmem 公共 API 与 C/C++ 标准库
- CLI 生产代码禁止:windows.h/tlhelp32.h 等平台头文件、任何第三方库、mock/fake 数据

## 3. 会话约定

- 会话生命周期=本次 CLI 进程:main 解析出 pid 后先 pmem::attach(pid),
  执行完命令 pmem::detach()
- 断点/watch/注入/壳码状态由 pmem 状态文件持久化,跨 CLI 调用保留
