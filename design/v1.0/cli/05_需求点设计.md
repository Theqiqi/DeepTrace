# CLI - 需求点设计

## 1. 需求点拆分

### 命令解析
- R1 全局选项解析(-p/--pid、-h/--help、-v/--version),支持 -p 前置或后置
- R2 命令路由:第一参数=命令组,第二参数=子命令,其余=参数
- R3 参数校验:数量、格式(地址/数字/字符串/类型枚举)
- R4 未知命令/缺参/非法参数 → 明确 ASCII 错误 + 用法提示
- R5 帮助输出:按组列出全部命令与参数说明

### 目标进程管理
- R6 未指定 pid 时,多数命令要求已附加(ps attach 建立的会话)
- R7 ps attach 建立 pmem 会话;ps detach 关闭
- R8 无交互:每次调用独立启动 pmem 会话(会话生命周期=本次 CLI 进程)

### 执行与输出
- R9 每个命令 → 对应 pmem 公共 API(一对一映射)
- R10 输出纯 ASCII;地址统一 16 进制 0x 前缀;字节 hex 双字符大写
- R11 错误时输出 pmem result_message + 非 0 退出码

## 2. 关键设计决策

- 会话:CLI 进程启动时若带 -p 且命令不是 ps list,先 pmem::attach(pid);
  命令执行完 pmem::detach()。断点/watch/注入记录由 pmem 状态文件跨调用保留。
- watch/DLL/壳码的状态持久化在 pmem 接口层,CLI 无状态。
- debug attach/detach 与 ps attach/detach 语义区分:debug attach 进入调试模式
  (调用 pmem::debug_attach),ps attach 为常规内存操作会话。

## 3. 输出编码约束

- 全部输出字符串仅 ASCII 可打印字符
- 进程/模块名为宽字符时,转换为 ASCII 可打印子集(不可打印 → '?')
- 禁止 getchar()/scanf()/cin 等阻塞式输入等待;无参运行直接输出后退出
