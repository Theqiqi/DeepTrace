## 2. API 能力覆盖性匹配

对照 08_能力需求列表.md 的改动点能力逐一匹配:

| # | CLI 能力需求 | 覆盖来源 | 结论 |
|---|--------------|----------|------|
| 1 | type 枚举校验 | CLI parser 既有枚举校验模式(标准库) | CLI 侧实现 ✓ |
| 2 | 按类型校验 value | CLI parser 校验框架(标准库) | CLI 侧实现 ✓ |
| 3 | 整数 → 小端字节(1/2/4/8) | 标准库 strtoull/memcpy | CLI 侧实现 ✓ |
| 4 | float/double → IEEE754 小端字节 | 标准库 strtof/strtod/memcpy | CLI 侧实现 ✓ |
| 5 | ASCII 字符串 → 逐字节 | 标准库字符处理 | CLI 侧实现 ✓ |
| 6 | 连续 hex → 空格分隔模式串 | 标准库字符串处理 | CLI 侧实现 ✓ |
| 7 | 按字节模式扫描目标进程内存 | **deeptrace::pattern_scan**(公共 API) | 静态库覆盖 ✓ |
| 8 | 单次调用自动 attach/detach | deeptrace::attach / detach(公共 API,既有) | 静态库覆盖 ✓ |

### 匹配结论

- 扫描能力(能力 7)与会话能力(能力 8)由静态库既有公共 API 完全覆盖:
  - `deeptrace::pattern_scan(const std::string& pattern, std::vector<uintptr_t>& out)`
    —— 接受空格分隔 hex 模式串(含 ?? 通配),扫描全部已提交可读非 GUARD 内存区域,
    返回命中地址。`value_to_pattern` 产出的模式串(如 `64 00 00 00`)可直接传入。
  - `deeptrace::attach(pid)` / `detach()` —— executor 既有自动会话逻辑。
- 能力 1-6 属于输入格式处理(类型枚举、数值/字符编码转换),允许且只能使用
  C/C++ 标准库实现(流程固定约定:CLI 生产代码只允许静态库公共 API + C/C++ 标准库)。
  这些不是"扫描能力"本身,不构成静态库缺失能力。
- **无缺失能力,不触发静态库流程**;deeptrace 零改动。
