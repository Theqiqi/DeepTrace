# CLI - 领域分析(修改模式)

> 引用:v1.0.0/cli/02_领域分析.md 既有领域模型。本版本为增量更新,仅标注与
> `resolve scan` 类型值输入相关的集合与操作变化,未改动集合引用既有文档。

## 1. 既有领域模型回顾(引用)

既有领域集合:进程集合、内存集合、模块集合、线程集合、调试集合、反汇编集合、
解析集合(resolve)、监视集合、注入集合、汇编集合、壳码集合。

- 解析集合(resolve)的操作:base(解析模块基址)、scan(按 AOB 模式扫描内存地址)

## 2. 改动点:解析集合 scan 操作增量

### 2.1 新增数据概念:扫描值(ScanValue)

scan 操作的可选参数 `type` 引入了"类型化扫描值"概念:

- **值(Value)**:用户输入的数据值,类型由 `type` 决定
- **类型(Type)**:byte / word / dword / qword / float / double / string / hex / pattern
  - 整数类型(byte/word/dword/qword):无符号十进制或 0x 前缀十六进制,小端字节序
  - 浮点类型(float/double):IEEE754 单/双精度,小端字节序
  - string:纯 ASCII 可打印字符序列,逐字节转换
  - hex:连续十六进制字节串(偶数长度)
  - pattern:既有 AOB 模式(含 ?? 通配),默认值,行为不变

### 2.2 新增操作流程:值 → 字节模式 → 扫描

```
用户输入 (value, type)
   → [转换] 按 type 生成十六进制字节模式串 (标准库实现)
   → [扫描] pattern_scan(模式串) 命中目标进程内存地址列表
```

这是对既有 scan 操作(模式串 → 扫描)的输入前置扩展:转换发生在 CLI 接口调用层,
扫描仍由静态库公共 API `pattern_scan` 完成,集合元素操作(查看)不变。

### 2.3 受影响集合/操作矩阵

| 集合 | 操作 | 变化 |
|------|------|------|
| 解析集合 | scan | 输入形式扩展(value+type),输出(命中地址列表)不变 |
| 解析集合 | base | 无变化 |
| 其他全部集合 | - | 无变化 |

## 3. 参与者与流程

- 参与者:CLI 调用者(脚本/AI 工具/用户),输入一行 `resolve scan <value> [type]`
- 操作流程:解析参数(校验 type 与按类型的 value)→ 自动 attach(-p pid)→
  value_to_pattern 转换 → pattern_scan → 打印命中地址 → 自动 detach → 退出

## 4. 结论

领域模型在既有"解析集合"上增量扩展 scan 操作,不新增命令组、不改变既有命令行为,
向后兼容(pattern 默认值)。
