# CLI - 代码审查结论(修改模式)

> 审查范围:v1.4.0 改动点涉及的受影响文件(commands.cpp / parser.cpp / cmd.h /
> executor.cpp / cmd_resolve.cpp / printer.cpp / CMakeLists.txt 及测试)。
> 未受影响模块引用既有审查结论。

## 6.1 目录结构审查

- cli/ 与 deeptrace/ 平级互不嵌套;改动仅落在 cli/ 内既有文件,无新增目录 ✓
- CLI 经 find_library 引用 deeptrace/out/lib/<配置>,无源码复制 ✓
- keystone/capstone 链接沿用既有 find_library,无变化 ✓

## 6.2 层级与无交互原则审查

- 命令层只构造请求对象;接口层经公共 API 调库;打印层只格式化 ✓
- 无 getchar/scanf/cin 等待;命令执行完立即退出 ✓
- 无跨调用状态;-p 单次调用内 attach/detach ✓

## 6.3 API 使用审查

- 唯一静态库调用为 `deeptrace::pattern_scan`,对应 09 能力匹配文档真实 API ✓
- `value_to_pattern` 仅用 C/C++ 标准库(strtoull/strtof/strtod/memcpy),无平台 API、
  无第三方库、无 mock/硬编码 ✓
- 能力完整性:声明的 8 种 type 均有实现;不支持形式(负数整数、非 ASCII 字符串、
  hex 浮点字面量、奇长 hex、类型值混用通配符)均有明确用法错误(退出码 2)✓
- 帮助文本未暗示未实现形式 ✓

## 6.4 模块职责审查

- main 只调度;parser 校验并构造请求;executor 执行;printer 输出 ✓
- cmd_resolve scan 分支职责:转换 + 调库 + 结果路由,无越界 ✓

## 6.5 代码质量审查

- 退出码语义一致(0 成功含无命中 / 1 业务错误 / 2 用法错误)✓
- 提前返回、嵌套深度符合既有风格 ✓
- 整数转换避开 strtoull base-0 的 "08" 八进制陷阱;浮点拒绝 hex 字面量与非有限值 ✓
- 所有输出字符串纯 ASCII ✓

## 6.6 规范与测试审查

- 测试层级:unit(parser/executor)+ integration(真实 target)+ e2e(独立 Python)✓
- 新增命令参数已配套正例(8 种 type 转换、范围边界)与负例(非法 type/value/
  hex 浮点/负数/非 ASCII)用例 ✓
- e2e 依赖既有独立体系,不参与 CMake ✓
- cases.md 已按改动点补充 ✓
