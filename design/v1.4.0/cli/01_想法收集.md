# CLI - 想法收集(修改模式)

## 1. 输入想法

**功能添加**:`resolve scan` 目前只接受 AOB 十六进制模式(如 `48 8B ?? ?? 00`),
用户希望直接输入**不同类型的数据值**(整数/浮点/字符串等),CLI 自动把该值转换成
十六进制字节(小端序),再按该字节模式在目标进程内存中扫描匹配地址。

例如:

- `resolve scan 100 dword` → 把 100 转成 dword 小端字节 `64 00 00 00` 再扫描
- `resolve scan 3.14 float` → 转成 IEEE754 单精度小端字节再扫描
- `resolve scan hello string` → 转成 ASCII 字节 `68 65 6C 6C 6F` 再扫描
- `resolve scan "48 8B ?? ?? 00"` → 不传类型,保持既有 AOB 模式(向后兼容)

## 2. 期望

- 修改现有命令组 `resolve` 的 `scan` 动作:增加可选 `type` 参数(默认 `pattern`,行为不变)
- 转换逻辑放在 CLI 接口调用层,只用 C/C++ 标准库实现(不调 OS API,不新增静态库能力)
- 全部输出仍为纯 ASCII;无交互约束不得被破坏(一次调用一个操作)
- 新增参数校验(类型枚举 + 按类型的值校验),错误消息纯 ASCII、退出码语义不变
  (0 成功 / 1 业务错误 / 2 用法错误)
- 静态库 deeptrace 不做任何改动:扫描能力完全复用既有 `pattern_scan` 公共 API

## 3. 涉及范围

- 命令层:`commands.cpp`(命令表/帮助)、`parser.cpp`(参数校验)
- 接口调用层:`cmd.h`、`executor.cpp`(转换辅助函数)、`cmd_resolve.cpp`(scan 流程)
- 打印层:仅版本号字符串更新,无需新增输出格式
- 测试:parser / executor 单元测试、集成测试(真实 target 内存命中)、e2e 用例
