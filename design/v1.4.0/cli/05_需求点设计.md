# CLI - 需求点设计(修改模式)

> 引用:v1.0.0/cli/05_需求点设计.md 既有需求点。本版本只对受影响需求点做增量更新。

## 1. 受影响需求点增量

### R1(修改):resolve scan 支持类型化值输入

- 用法:`resolve scan <value> [type]`
- `type` 可选,默认 `pattern`;取值范围:`byte|word|dword|qword|float|double|string|hex|pattern`
- 转换规则:
  - byte/word/dword/qword:无符号十进制或 0x 前缀十六进制 → 按宽度小端字节
    (byte=1/word=2/dword=4/qword=8)
  - float/double:十进制浮点(含科学计数)→ IEEE754 小端字节(4/8 字节)
  - string:纯 ASCII 可打印字符(0x20-0x7E)逐字节
  - hex:连续十六进制字节串(偶数长度,可选 0x 前缀)
  - pattern:既有 AOB 模式(空格分隔字节,?? 通配),直接透传
- 输出不变:命中地址列表(每行一个 `0x%016llX`),无命中输出 `No match found`

### R2(新增):值合法性校验

- type 必须为枚举之一,否则 `Error: invalid type: '<t>'`,退出码 2
- value 必须匹配 type 语义,否则 `Error: invalid value for type '<t>': '<v>'`,退出码 2
- 校验规则:
  - 整数:十进制或 0x 十六进制,无符号,按类型宽度检查范围(byte ≤ 0xFF,word ≤ 0xFFFF,
    dword ≤ 0xFFFFFFFF,qword ≤ 0xFFFFFFFFFFFFFFFF);负数/非数字 → 非法
  - float/double:strtof/strtod 全串解析成功且有限(非 inf/nan),否则非法
  - string:非空,全部字符为 ASCII 可打印(0x20-0x7E)
  - hex:非空偶数长度,仅 0-9a-fA-F(可选 0x 前缀)
  - pattern:沿用既有 valid_pattern 规则(1-64 字节,?? 或双 hex 字符)

### R3(新增):类型值 → 字节模式转换(value_to_pattern)

- 接口调用层内部函数,输入已通过校验的 value+type,输出空格分隔大写 hex 模式串
  (如 `64 00 00 00`),直接作为 `deeptrace::pattern_scan` 的模式参数
- 纯 C/C++ 标准库实现,禁止 OS API / 静态库内部头文件

## 2. 约束复查

- 无交互约束:新增路径不引入任何 getchar/scanf/cin 等待;命令执行完立即退出 ✓
- 纯 ASCII 输出约束:帮助文本、错误消息、命中输出均保持纯 ASCII ✓
- 会话生命周期:scan 仍经 `-p <pid>` 单次调用内自动 attach/detach ✓
- 资源配对:attach/detach 路径复用既有 executor 逻辑,不新增成对资源 ✓
