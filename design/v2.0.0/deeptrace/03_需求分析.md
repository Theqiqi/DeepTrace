# deeptrace - 需求分析(修改模式)

> 引用:v1.2.0/deeptrace 既有需求文档。本版本聚焦 debug_continue 需求。

## 1. 需求描述

CLI 脚本步骤 `continue` 需要静态库在调试模式下:
1. 恢复目标进程执行(处理挂起的初始调试事件);
2. 等待下一个调试事件,在超时时间内返回;
3. 区分并报告四种结果:命中软件断点(消费:恢复原字节→单步→重新武装→报告)、
   其他异常(报告,不消费)、进程退出(报告退出码)、超时(报告 timeout)。

## 2. 需求点

| # | 需求点 | 验收 |
|---|--------|------|
| 1 | debug_continue 公共 API + ContinueInfo 数据结构 | 声明于 deeptrace.h / domain/types.h |
| 2 | 软件断点命中消费流程 | 集成测试:命中后原字节恢复、INT3 重新武装、地址/RIP 正确、目标暂停 |
| 3 | 其他异常/退出/超时报告 | 集成测试 |
| 4 | 分层与兼容 | Service 组装、Infrastructure 原语;既有 API 不变 |

## 3. 无新三方依赖

纯 Windows API(Win32 调试事件)实现,不新增依赖。
