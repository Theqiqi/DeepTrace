# deeptrace - 想法收集

## 1. 输入想法

CLI v2.0.0「脚本驱动的一次性调试会话」需要「运行到断点」能力:
脚本中执行 continue 步骤后,目标进程恢复运行,直到命中已设置的软件断点
(或其他异常)、进程退出或超时,并把结果(命中地址/RIP/异常码/退出码/超时)交回脚本。

静态库现有能力:debug_attach/detach、pause/resume、单步(debug_step/step_over)、
软件/硬件断点、守护页、寄存器。**缺"继续运行并等待下一个调试事件"的公共 API**。

## 2. 期望(整理)

- 公共 API:`Result debug_continue(uint32_t timeout_ms, ContinueInfo& out)`
  - 输入:超时毫秒
  - 输出:ContinueInfo{hit, exited, exit_code, exception_code, address, rip, tid}
  - 语义(见 00_CHANGELOG):软件断点命中被消费(恢复原字节→单步执行断点指令→
    重新武装 INT3→报告地址与执行后 RIP,目标保持暂停);其他异常报告不消费;
    进程退出报告退出码;超时报告 timeout。命中/超时均 Ok,失败返回 Error/AccessDenied。
- 约束:纯 Windows 调试事件(WaitForDebugEvent)机制实现,真实底层能力,禁止模拟。
