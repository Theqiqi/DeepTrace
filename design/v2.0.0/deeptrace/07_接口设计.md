# deeptrace - 接口设计(修改模式)

> 引用:v1.2.0/deeptrace/10_接口设计.md。本版本新增接口细节:

## 1. debug_continue

- 前置:`attach(pid)` + `debug_attach()` 完成;`timeout_ms > 0`。
- 流程:
  1. `DebugWaitEvent(pid, timeout_ms, out)`:先处理挂起的初始事件
     (继续直到 CREATE_PROCESS 被继续,使目标运行;若无挂起事件则短超时跳过),
     再在超时预算内等待调试事件:
     - EXCEPTION_DEBUG_EVENT → 填充 hit/exception_code/address/tid/rip(读线程
       上下文),**不继续该事件**(目标冻结),返回;
     - EXIT_PROCESS_DEBUG_EVENT → exited/exit_code,返回;
     - 其余事件 → ContinueDebugEvent(DBG_CONTINUE) 继续等待;
     - WaitForDebugEvent 超时 → 返回 Timeout(上层转 timeout 报告)。
  2. 若 hit 且异常码为 EXCEPTION_BREAKPOINT 且 address 在持久化软件断点记录中:
     `DebugConsumeBreakpoint(pid, tid, address, orig, &rip)`,填充 out.rip 后返回。
  3. 其余情况直接返回 out。

## 2. DebugConsumeBreakpoint

- 前置:断点异常事件挂起(线程冻结于 address,RIP=address)。
- 流程:写回原字节 → 线程设 TF → ContinueDebugEvent(DBG_CONTINUE) → 等待该线程
  EXCEPTION_SINGLE_STEP → 读执行后 RIP → 写回 0xCC 重新武装 → 继续事件 → 返回。

## 3. 异常与错误

- NotAttached / InvalidArg / Timeout / Error;ContinueInfo 缺省全零。
