# deeptrace - 跨流程需求接收记录(design/v2.0.0/deeptrace/02_需求接收记录.md)

> 关联交接记录:design/v2.0.0/cli/09_静态库流程交接记录.md(CLI v2.0.0 发起)。

## 1. 接收清单(逐项)

| 项 | 内容 |
|----|------|
| 缺失能力 | 运行到断点(continue):调试模式下恢复目标执行,等待下一个调试事件并报告 |
| 期望公共 API | `Result debug_continue(uint32_t timeout_ms, ContinueInfo& out)` |
| 输入 | 超时毫秒(>0) |
| 输出 | ContinueInfo{hit, exited, exit_code, exception, address, rip, tid} |
| 异常要求 | 非调试模式 → NotAttached;timeout_ms==0 → InvalidArg;WaitForDebugEvent 失败 → Timeout/Error;命中与超时均 Ok |
| 验收标准 | ①软件断点命中被消费(恢复原字节→单步执行断点指令→重新武装 INT3→报告断点地址与执行后 RIP,目标保持暂停);②其他异常(硬件断点/守护页)报告异常码与地址、不消费;③进程退出报告退出码;④超时报告 timeout。真实 target 集成测试验证 |

## 2. 约束确认

- 使用真实 Windows 调试事件机制(DebugActiveProcess + WaitForDebugEvent/
  ContinueDebugEvent),禁止模拟数据/硬编码/伪造。
- 分层:基础设施层实现事件等待与断点消费原语,Service 层组装(含断点记录判定)。
- 既有公共 API 全部保持兼容;会话(debug_mode)语义不变。
- 接收完成,进入需求分析。
