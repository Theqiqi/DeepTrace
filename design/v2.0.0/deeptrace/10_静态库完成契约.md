## 4. CLI 缺失能力覆盖结果

CLI 交接记录(design/v2.0.0/cli/09_静态库流程交接记录.md)列出的缺失能力逐项确认:

| 缺失能力 | 覆盖 API | 结果 |
| --- | --- | --- |
| 脚本会话中的「运行到断点」 | `debug_continue(timeout_ms, ContinueInfo&)` | 已实现 |
| 断点命中后的停止原因(异常码/地址/线程/RIP) | `ContinueInfo{hit, exited, exit_code, exception, address, rip, tid}` | 已实现 |
| 断点消费(恢复原字节→单步→重新武装) | 内部 `DebugConsumeBreakpoint` | 已实现 |
| 附加时系统断点过滤 | 内部 `DebugWaitEvent(sw_addrs)` 跳过非挂起断点地址的 int3 | 已实现 |
| detach 前挂起事件排空(防目标崩溃) | `debug_detach` 事件排空 + RIP 回退 | 已实现 |

## 5. 未解决问题

- `debug_continue` 报告除软件断点外的异常(hit=true)但不消费,目标保持冻结;脚本会话
  需要决定如何处理(记录后继续或终止)。
- 断点命中后 RIP 为执行后 RIP(软件断点),与部分调试器「命中即断在 int3 前」的
  语义不同;CLI 脚本设计需据此对齐输出。
- 硬件断点/守护页命中不经过 `DebugConsumeBreakpoint`(仅软件断点消费),continue
  返回 hit 后由 CLI 层决定。
