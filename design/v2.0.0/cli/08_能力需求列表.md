# CLI - 能力需求列表(修改模式)

> 只回答"CLI 需要做什么",不回答"用什么做"。聚焦改动点新增能力需求。

## 1. 改动点能力需求

| # | 能力需求 | 说明 |
|---|----------|------|
| 1 | 读取脚本文件(文本) | std::ifstream(标准库) |
| 2 | 解析 JSON 步骤数组(字符串值子集) | 自实现小解析器(标准库;CLI 禁第三方库) |
| 3 | 步骤校验(操作表/必填字段/字段取值) | 自实现(标准库) |
| 4 | 一次会话内逐条执行调试/内存/反汇编/监视操作 | 复用静态库公共 API |
| 5 | 运行到断点(continue):恢复目标执行并等待下一次调试事件(命中/异常/退出/超时) | **缺失能力 → 静态库流程** |
| 6 | 会话清理:恢复本次设置的软/硬断点与守护页 | 复用 breakpoint_clear/hw_breakpoint_clear/guard_clear |
| 7 | 步骤输出格式化(逐步头 + 结果) | 复用打印层 |

## 2. 能力覆盖判断

- 1/2/3:CLI 标准库自实现(与既有 hex_bytes/转换辅助同级)。
- 4/6:既有公共 API 覆盖,直接复用。
- 5:静态库无对应 API(只有单步,无"继续+等待事件")→ **缺失能力**,
  进入静态库流程新增 `debug_continue`;静态库完成契约返回后重新匹配。
- 结论:仅 continue 一项走静态库流程,其余全部既有能力覆盖。
