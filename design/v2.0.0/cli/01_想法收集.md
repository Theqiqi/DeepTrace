# CLI - 想法收集(修改模式)

## 1. 输入想法

当前 CLI 是无状态入口:一次调用一个操作。但**动态调试**本质依赖**有状态的调试会话**
(断点、暂停、单步位置、命中状态),单命令入口下多步调试只能跨多次调用进行,
会话状态散落在持久化文件(%TEMP%/deeptrace_<pid>/breaks.dat)与一次次 attach/detach 中,
动态分析、静态分析、动态调试混在同一命令面上,使用体验不清晰。

**期望**:用**文件/脚本写成清晰的步骤**,一次动态调试 = 一次完整的调试会话;
所有会话只存在于本次调用;调试会话状态依旧在内存中。

## 2. 设计方向(参考 gdb 一次性脚本,但更简洁清晰)

- 命令:`deeptrace_cli -p <pid> debug run <script>`(沿用既有 debug 组)。
- 脚本 = JSON 步骤数组(用户示例为 .json,字段显式、AI 可生成、避免参数歧义):
  ```json
  [
    {"op": "break", "addr": "0x140001000"},
    {"op": "continue", "timeout_ms": "5000"},
    {"op": "registers"},
    {"op": "step"},
    {"op": "read", "addr": "0x140001000", "size": "16", "format": "hex"},
    {"op": "clear", "addr": "0x140001000"}
  ]
  ```
- 步骤覆盖:调试(break/clear/hbreak/hclear/guard/unguard/pause/resume/step/next/
  registers/register/status/continue)+ 内存(read/write)+ 反汇编(disasm)+ 监视(watch_*)。
- 一次调用流程:attach(-p)→ debug_attach → 逐条执行步骤 → 清理本次会话设置
  (软/硬断点、守护页)→ debug_detach → detach。会话状态全程在内存中。
- CLI 约束:无阻塞等待、纯 ASCII、一次调用一个操作(本功能即一个操作:跑一个脚本)、
  退出码语义 0/1/2 不变。

## 3. 静态库能力缺口

- 脚本需要「运行到断点」步骤(continue):静态库目前只有单步(debug_step/step_over),
  无"继续运行直到命中断点/退出/超时"的 API → **缺失能力,触发静态库流程**。

## 4. 涉及范围

- CLI:commands.cpp(debug run 命令表)、script.cpp(JSON 解析+校验)、
  cmd_debug_run.cpp(会话执行器)、cmd_debug.cpp(run 分派)、版本 2.0.0。
- 静态库:新增 `debug_continue` + `ContinueInfo`(走库流程)。
- 测试:script 单元、CLI 集成(真实目标脚本会话)、e2e、库集成(continue 命中/超时)。
