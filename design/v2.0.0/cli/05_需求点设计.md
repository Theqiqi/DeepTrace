# CLI - 需求点设计(修改模式)

> 引用:v1.0.0/cli/05_需求点设计.md。本版本只对受影响需求点做增量更新。

## 1. 需求点:debug run(新增)

### 1.1 命令与参数

- `deeptrace_cli -p <pid> debug run <script>`:script 为脚本文件路径(必填)。
- 需要 `-p <pid>`(executor 自动 attach 进程会话;缺省时 debug_attach 失败报错退出 1)。

### 1.2 脚本格式(JSON 步骤数组)

- 顶层为数组,元素为对象;对象字段均为**字符串值**(地址/数值/格式等显式字符串)。
- 每步必含 `op`;其余字段按操作表校验(必填字段缺失 → 校验错误)。
- 操作表(共 22 个):
  - 调试:break(addr)、clear(addr)、hbreak(addr,type?,len?)、hclear(addr)、
    guard(addr,size)、unguard(addr,size)、pause、resume、step(tid?)、next(tid?)、
    registers(tid?)、register(name,tid?)、status、continue(timeout_ms?)
  - 内存:read(addr,size?,format?)、write(addr,value,format?)
  - 反汇编:disasm(addr,count?)
  - 监视:watch_list、watch_add(desc,addr,type)、watch_remove(index)、
    watch_refresh、watch_clear

### 1.3 会话流程与语义

1. 读取并解析脚本(文件不存在/JSON 格式错/操作未知/字段缺或非法 → 退出 2)
2. `debug_attach()` 进入调试模式(失败 → 退出 1)
3. 逐条执行步骤,每步输出以 `[N] op [args]` 开头,后接该步骤结果;失败即停:
   - 输出 `Error: step N (<op>): <消息>`,清理后退出 1
   - continue 语义:目标运行至 命中软件断点(打印 `breakpoint hit at <addr>
     (rip = <rip>)`,目标保持暂停)/ 其他异常(打印 `exception 0x<code> at <addr>`)
     / 进程退出(打印 `process exited (code N)`,脚本停止,退出 1)
     / 超时(打印 `continue timeout (<ms> ms)`,步骤成功,继续下一行)
4. 清理(成功与失败均执行):清除本次脚本设置的软件断点(恢复原字节)、硬件断点、
   守护页;`debug_detach()`;executor 再 detach 进程会话
5. 成功退出 0

### 1.4 输出格式(纯 ASCII)

```
[1] break 0x140001000
breakpoint set at 0x0000000140001000 (orig 0x8B)
[2] continue
breakpoint hit at 0x0000000140001000 (rip = 0x0000000140001002)
[3] registers
...
debug session done (3 steps)
```

### 1.5 约束满足确认

- 无等待 ✓(文件 I/O + 会话执行,无用户输入等待)
- 纯 ASCII ✓;一次调用一个操作 ✓
- 资源配对:断点设置/清除、guard 设置/恢复、debug_attach/detach、attach/detach
  均成对,测试阶段副作用检查验证 ✓
