# CLI - 静态库能力匹配(修改模式)

## 1. 静态库存在性匹配

- 静态库存在:deeptrace(公共头 deeptrace.h,产物 out/lib/<配置>/deeptrace.lib,v1.3.0)。
- 继续「API 能力覆盖性匹配」。

## 2. API 能力覆盖性匹配

| CLI 能力需求 | 提供方 | 覆盖 |
|--------------|--------|------|
| 脚本文件读取/JSON 解析/步骤校验 | CLI(标准库,自实现小解析器) | 无需静态库 |
| 会话内调试/内存/反汇编/监视操作 | 既有公共 API(debug_*/memory_*/disasm_at/watch_*) | 覆盖 |
| 会话清理(软/硬断点、守护页) | breakpoint_clear/hw_breakpoint_clear/guard_clear | 覆盖 |
| **运行到断点(continue)** | **无对应 API**(仅有 debug_step/step_over,无"继续+等待事件") | **缺失** |

### 匹配结论

- 缺失能力 1 项:`debug_continue`(运行到断点,报告命中/异常/退出/超时)。
- 其余能力全部覆盖;静态库流程被触发(见交接记录)。

## 3. 静态库流程交接记录(design/v2.0.0/cli/09_静态库流程交接记录.md)

- 跳转目标:cpp_static_flow.md「跨流程需求接收」步骤。
- 缺失能力、期望公共 API、输入输出、异常要求、验收标准见交接记录文档。
- CLI 在静态库完成契约返回前,不实现接口调用层的 continue 相关代码。
