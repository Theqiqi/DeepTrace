# CLI - 业务流程分析(修改模式)

> 引用:v1.0.0/cli/06_业务流程分析.md。本版本重画 debug run 业务流程。

## 1. debug run 业务流程(新增)

```
编写脚本文件(JSON 步骤数组)
   │
   ▼
deeptrace_cli -p <pid> debug run <script>
   │
   ├─ 读取/解析/校验脚本 ──失败──► Error + 退出码 2
   │
   ▼
executor attach(pid)(-p 自动会话)
   ├─ 失败 ──► Error + 退出码 1
   ▼
debug_attach() 进入调试模式(目标线程冻结,等待首次 continue/step 释放)
   ├─ 失败 ──► Error + 退出码 1
   ▼
逐条执行步骤(循环)
   ├─ 步骤失败 ──► Error: step N (<op>): ...  ──► 清理 ──► 退出码 1
   ├─ continue 命中断点 ──► 打印命中地址/RIP(目标暂停,继续下一行)
   ├─ continue 其他异常 ──► 打印异常码/地址(继续下一行)
   ├─ continue 进程退出 ──► 打印退出码 ──► 停止脚本 ──► 退出码 1
   ├─ continue 超时 ──► 打印 timeout(步骤成功,继续下一行)
   └─ 全部步骤完成 ──► 打印 debug session done ──► 清理 ──► 退出码 0
   │
   ▼
清理(清除本次软/硬断点、守护页)→ debug_detach() → detach()
```

- 单条命令边界:一次调用一个完整会话;会话状态(调试模式、断点、命中位置)
  仅存在于本次进程内存,调用结束即释放。
- 既有单命令(内存/反汇编/监视/扫描/断点单步等)业务流程不变。
