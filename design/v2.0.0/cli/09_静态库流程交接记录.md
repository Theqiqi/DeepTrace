## 1. 缺失能力清单(逐项)

### 能力 1:运行到断点(continue)

| 项 | 内容 |
|----|------|
| 缺失能力 | 在调试模式下恢复目标进程执行,等待下一个调试事件并报告结果 |
| 期望公共 API | `Result debug_continue(uint32_t timeout_ms, ContinueInfo& out)` |
| 输入 | 超时毫秒(0 = 无限?本期限定 >0,超时报告 timeout) |
| 输出 | ContinueInfo{hit, exited, exit_code, exception, address, rip, tid} |
| 异常要求 | 未进入调试模式 → NotAttached;WaitForDebugEvent 失败 → Error;命中/超时均 Ok |
| 验收标准 | ①软件断点命中:恢复原字节、单步执行断点指令、重新武装 INT3,报告断点地址与执行后 RIP,目标保持暂停;②其他异常(硬件断点/守护页):报告异常码与地址,不消费;③进程退出:报告退出码;④超时:报告 timeout。以上在真实 target 集成测试中验证 |

## 2. 需求方约束

- 静态库实现必须使用真实 Windows 调试事件机制(DebugActiveProcess +
  WaitForDebugEvent/ContinueDebugEvent),禁止模拟数据/硬编码结果。
- 保持既有 API 全部兼容;会话(debug_mode)语义不变。
- CLI 侧将按该 API 在脚本步骤中调用;契约缺少公共头/API/产物/测试证据不得通过。
