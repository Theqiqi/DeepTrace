# v1.2 分析与设计(修改模式,仅受影响部分)

> 修改模式:只分析改动点,未受影响内容引用 v1.1 既有文档(08_模块设计 / 09_职责和边界设计 / 10_接口设计 / 11_技术选型 / 12_代码规范)。

## 1. 需求分析(改动点)

### 改动点 1:基础设施层职责修正(assembly 独立目录)

- **现状问题**:`infrastructure/disassembly/` 同时含 asmenc(keystone 汇编)与 disasm(反汇编)——汇编与反汇编是两类不同能力,混放导致目录名与内容不符,职责边界模糊。
- **修正**:按流程约定"Infrastructure 内按能力类型分子目录",新建 `infrastructure/assembly/` 承载汇编(asmenc),`infrastructure/disassembly/` 只承载反汇编(disasm)。
- **影响**:文件路径变更(asmenc 移动),依赖引用同步更新(service/asm.cpp、unit/asm_test.cpp、src/CMakeLists.txt);asmenc 内容本身不变。

### 改动点 2:反汇编引擎替换为 Capstone

- **现状问题**:自研 x64 解码器为手写子集(~26KB),指令覆盖不全(SSE/SSE2/REP 字符串等无法解码),"解码不了就静默停",且维护成本高。
- **修正**:`disassembly/disasm` 内部实现切换为 Capstone 5.0.9,仅启用 x86-64 后端。
- **能力边界**:解码覆盖 = Capstone x86-64 全量指令集;非法/截断字节流返回 false(与现接口语义一致,由调用方停止解码)。
- **输出格式**:解码文本采用 Capstone Intel 语法规范格式,是引擎替换带来的预期行为变化,单元测试断言同步更新(见 03_接口设计)。

## 2. 业务流程分析

- 反汇编业务流程不变:`disasm_at/disasm_range` → 会话 attach → 远程读内存 → 逐条 `disasm_one` 解码 → 输出 Instruction 列表。仅"逐条解码"这一能力提供方由自研改为 Capstone。
- 汇编业务流程不变(keystone 已在 v1.1.1 完成,本次仅迁目录)。

## 3. 功能点设计

| 功能点 | 归属 | 本次变化 |
|--------|------|---------|
| 汇编单指令(asm_one) | infrastructure/assembly | 迁目录,实现不变(keystone) |
| 反汇编单指令(disasm_one) | infrastructure/disassembly | 实现替换为 capstone,接口不变 |
| 服务层组装(asm_assemble / disasm_at / disasm_range) | service | include 路径更新,逻辑不变 |
| CLI 命令(asm/disasm) | cli | 零改动(公共 API 不变) |

## 4. 接口设计(关键决策)

- **基础设施接口不变**:`asm_one(line, out)`、`disasm_one(bytes, max_len, address, DecodedInsn&)`、`DecodedInsn{uint8_t length; std::string text;}`——三个接口签名全部保持不变,Service 层与测试仅需改 include 路径。
- **公共 API 不变**:pmem.h 的 `asm_assemble`、`disasm_at`、`disasm_range` 零改动。
- **输出格式变化(仅 disasm text)**:手写格式 `mov rax, [rbp+0x8]` → Capstone 格式 `mov rax, qword ptr [rbp + 8]`;imm64 手写 `mov` → Capstone `movabs`。这是引擎替换的预期结果,由 unit/disasm_test.cpp 断言锁定。

## 5. 技术选型(反汇编引擎)

| 项 | 结论 |
|----|------|
| 库 | **Capstone 5.0.9**(BSD-3 许可,维护活跃,c/shell 通用反汇编框架) |
| 后端 | 仅 x86-64(CAPSTONE_X86_SUPPORT=ON) |
| 包管理 | 手动下载源码到 `pmem/third_party/capstone`,**不入库只留收据** |
| 理由 | 本环境已实测 vcpkg 的 capstone port 默认禁用全部架构(cs_open 返回 CS_ERR_ARCH,sandbox 验证记录);手动下载源码 + 仅启用 x86 后端构建快、可控;keystone 同款模式已在 pmem 验证可用 |
| 构建 | `add_subdirectory(third_party/capstone ... EXCLUDE_FROM_ALL)`,关闭 tests/cstool/cstest/install |
| 自实现 vs 开源库 | 开源库(按代码规范"自实现要功能完整+审查+测试,开源库要验证稳定好用")——capstone 已通过 sandbox 独立验证(断言通过)与本项目单元测试覆盖 |
