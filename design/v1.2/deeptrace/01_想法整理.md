# v1.2 想法整理

## 原始想法(不成形)

核查发现架构问题:基础设施层没有 `assembly` 目录,但 CMake 与项目里出现了 keystone——keystone 汇编能力(asmenc)被错误地放进了 `infrastructure/disassembly/` 目录,与反汇编混在一起,职责没分清。

需求输入:**用 keystone 替换汇编引擎(已完成,见 v1.1.1),用 capstone 替换反汇编引擎**。

## 整理结果

| 项 | 内容 |
|----|------|
| 程序类型 | 静态库 deeptrace 修改(基础设施层),CLI 公共 API 不变 |
| 改动点 1 | **职责修正**:汇编能力独立为 `src/infrastructure/assembly/`(asmenc 从 disassembly/ 迁出),反汇编保留在 `src/infrastructure/disassembly/` |
| 改动点 2 | **反汇编引擎替换**:`disassembly/disasm` 内部实现由自研 x64 子集解码器切换为 Capstone(开源库) |
| 期望行为 | 汇编(asm 指令→字节)与反汇编(字节→指令文本)两类能力各自独立目录、实现完整、覆盖充足 |
| 验收标准 | ①disasm 单指令接口与 DecodedInsn 结构不变,service/公共 API/CLI 零改动;②单元测试断言更新为 Capstone 输出格式;③Debug/Release 编译通过、全量测试回归通过 |
