# CLI - 想法收集(v2.4.0,修改/添加功能模式)

## 1. 输入想法(原始)

> 用户问:「此脚本功能有没有添加对语法的检查?」
> 确认现状:已有两层检查(解析期 aa_parse_text 语法检查 + 执行期校验),但都是
> **执行命令(run/disable)的组成部分**,错误只在执行前/执行中暴露,没有一个
> 「只检查不执行」的独立入口。
> 用户意图(经 ask_user 确认):新增 **`script check` 命令**,只检查脚本语法、
> 不执行任何目标操作,可用于 CI/编辑器校验。

## 2. 想法解读

- 用户需要一个**纯校验命令**:输入脚本文件,输出「语法是否合法」的判定,不 attach、
  不分配、不写入、不执行——任何目标操作都不做。
- 现有检查已覆盖两层:
  - **解析期**(`aa_parse_text`):块标记/关键字调用/参数/标签/db 十六进制/块作用域,
    错误 → `Error: script parse error at line N: ...` 退出 2。
  - **执行期**:Keystone 汇编校验指令合法性、hook 块结构、模块加载、未定义符号 → 退出 1。
- 差距:执行期检查(汇编指令合法性、hook 块结构)只在 run 时(attach 后)才暴露,
  check 应在**不 attach** 的情况下提前发现这些静态可判定问题。

## 3. 现状差距分析

| 能力 | 现状 | 差距 |
|------|------|------|
| 语法解析检查 | `aa_parse_text`(解析期,run/disable 内) | 无(复用) |
| 汇编指令合法性预检 | 仅 run 执行时(attach 后 Keystone 汇编) | check 需不 attach 提前检查 |
| hook 块结构静态校验 | 仅 run 执行时(resolve_enable/exec_enable 内) | check 需静态复现 |
| 独立校验命令 | 无 | 需新增 `script check` |
| 退出码语义 | 解析错误 2 / 执行错误 1 | check 失败统一 2(输入问题) |

## 4. 流程可行性

- 类型:修改/添加功能(对现有 CLI 的 script 命令组添加一个子命令)。
- 程序类型沿用:CLI 无交互,一次调用一个操作(`script check <file>` 一次调用完成校验)。
- 能力匹配:汇编预检复用静态库**已有公共 API** `asm_assemble_labels`
  (纯本地汇编,无需 attach——v2.3.0 已验证),**无需走静态库流程**。
- 版本号:v2.4.0(功能位 +1)。
