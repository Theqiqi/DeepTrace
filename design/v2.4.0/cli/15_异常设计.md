# CLI - 异常设计(修改模式,增量,v2.4.0)

> 引用:v2.3.0/cli/15_异常设计.md。v2.4.0 新增 script check 错误路径与退出码如下,其余不变。

## 1. 错误消息格式(沿用)

统一 `Error: <消息>` 前缀,纯 ASCII,输出到 stderr。

## 1.5 script check(新增)

| 场景 | 退出码 | 消息示例 |
|------|--------|----------|
| 文件不存在/不可读 | 2 | `Error: cannot read file: x.aa` |
| 语法错误(复用 aa_parse_text) | 2 | `Error: script parse error at line 3: ...` |
| hook 块结构错误(目标后非 jmp / jmp label 未定义) | 2 | `Error: script check failed at line 5: hook target must be followed by 'jmp <label>'` |
| 汇编预检失败(未知指令/非法操作数) | 2 | `Error: script check failed at line 8: BadFormat` |
| 通过 | 0 | `OK (N steps: ...)` |

- check **无退出 1**:不 attach、不执行,不存在业务/目标/库错误;
  所有失败均为输入/脚本问题 → 退出 2。
- check 不校验模块加载(`"module"+offset` 引用的模块是否已加载)、不做 alloc/write/
  线程等动态操作——这些留到 run 时校验(退出 1);文档不暗示 check 能发现动态错误。

## 2. 新增错误路径与退出码

| 命令 | 场景 | 退出码 | 消息示例 |
|------|------|--------|----------|
| script run/disable | 文件不存在/不可读 | 2 | `Error: cannot read file: x.aa` |
| script run/disable | 脚本语法错误(未知关键字/括号不匹配/未知块) | 2 | `Error: script parse error at line 3: unknown keyword 'foo'` |
| script run | 无 [ENABLE] 块 | 2 | `Error: script has no [ENABLE] block` |
| script disable | 无 [DISABLE] 块 | 2 | `Error: script has no [DISABLE] block` |
| script run/disable | 未 attach(-p 缺失/失败) | 1 | `Error: NotAttached` / `Error: attach: NoSuchProcess` |
| script run | 模块地址表达式模块未加载 | 1 | `Error: NotFound: module` |
| script run | alloc 重复符号/大小 0 | 1 | `Error: InvalidArg` |
| script run | 汇编失败(未知指令/未定义 label) | 1 | `Error: BadFormat` |
| script run | hook 改写失败/写失败 | 1 | `Error: WriteFault` |
| script run | createThread 失败 | 1 | `Error: Error` |
| script disable | hook 恢复失败 | 1 | `Error: WriteFault`(记录保留可重试) |
| script disable | dealloc 符号不存在 | 1 | `Error: NotFound` |

## 3. 幂等与回滚

- **幂等**:`script run` 执行前查 `script_status`(静态库按 PID+路径持久化),
  已启用 → `already enabled` 退出 0(不重复执行);`script disable` 未启用 →
  `already disabled` 退出 0。
- **ENABLE 失败回滚**:中途失败 → 已 alloc 的符号 `script_free`、已 hook 的目标
  `hook_clear`,保证一次调用无残留。
- **DISABLE 失败**:hook 恢复失败返回错误(记录保留,可重试);dealloc 失败返回错误。

## 4. 异常边界

- 无阻塞等待:全部命令立即返回;不等待远程线程结束(createThread 为触发语义)。
- 能力边界(声明支持/不支持):
  - 脚本支持关键字与语法见 12_接口设计;汇编行仅支持 x64 指令,符号引用仅限
    jmp/call(非 jmp/call 引用符号 → BadFormat);
  - 不支持:跨进程符号、模块未加载的地址表达式(含 alloc near 表达式引用未
    加载模块 → NotFound 退出 1);
  - `alloc` 的 near 第三参数(如 `alloc(newmem,2048,"game.dll"+7D5778)`)接受
    为**放置提示**:解析并校验表达式(模块必须已加载/地址合法),但分配位置
    仍由 OS(VirtualAllocEx)决定——文档明确:不保证就近放置。
  - hook 覆盖长度固定 5 字节(jmp rel32);hook 目标后仅支持 `jmp <label>` 与
    CE 填充行(`nop N`/`db`/标签),其他语句 → 脚本错误退出 1。
- 退出码语义:0 成功 / 1 业务错误(目标/库/资源问题)/ 2 用法错误(参数/文件/输入)。
