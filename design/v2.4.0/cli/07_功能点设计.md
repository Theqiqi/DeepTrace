# CLI - 功能点设计(修改模式,增量,v2.3.0)

> 引用:v2.2.0/cli/07_功能点设计.md 既有功能点。本版本新增 script 组相关功能点。

## 1. 功能点:脚本解析(AA 语法 → 结构化步骤)

### 1.1 功能分析

- 输入:脚本文件路径(AA 风格,UTF-8 纯 ASCII)。
- 解析规则(静态库或 CLI 解析器,确定性规则):
  1. 按行读取,去掉注释(`//` 至行尾)与空行。
  2. 识别块标记 `[ENABLE]`/`[DISABLE]`,按块分组。
  3. 每行匹配:关键字调用(`alloc(name,size)` 等)、标签定义(`<name>:` 或 `"module"+offset:`)、裸汇编行、`db <hex>`。
  4. 输出:块 → 步骤序列(步骤类型 + 参数 + 文本)。
- 错误路径:未知关键字/语法错误/括号不匹配/未知块 → `Error: script parse error at line N: <msg>` + 退出 2。
- 能力边界:只支持文档列出的关键字与语法;不支持 CE 的完整语法(如汇编内嵌条件、多脚本复合等 → 明确报错)。

### 1.2 功能流程

```
parse_script(path):
  lines = read_lines(path)                --fail--> Error + 2
  blocks = split_blocks(lines)            --语法错--> Error + 2
  for each line in block: classify(line)  --语法错--> Error + 2
  return steps
```

## 2. 功能点:script run(执行 ENABLE,幂等)

### 2.1 功能分析

- 输入:脚本文件路径(经 `-p` attach 目标进程)。
- 执行:
  1. 解析脚本 → ENABLE 步骤(无 ENABLE → 退出 2)。
  2. 幂等检查:`script_is_enabled(pid, script_path)` → 已启用 → 输出 `already enabled` 退出 0。
  3. 顺序执行步骤:label 收集 → alloc(分配+符号)→ 汇编写入 → db 写入 → hook 改写 → createThread → registersymbol。
  4. 全部成功 → 持久化脚本记录(已启用)。
- 输出:每步摘要(alloc 地址 / createThread TID / hook 目标与字节)。
- 错误路径:未 attach → 退出 1;任一步失败 → 回滚(释放已分配、恢复已改写)→ 退出 1。
- 退出码:0 成功 / 1 业务错误 / 2 用法错误。

### 2.2 功能流程

```
cmd_script run:
  steps = parse_script(path)              --fail--> Error + 2
  block = steps[ENABLE]                   --无--> Error + 2
  if script_enabled(pid, path): print "already enabled"; return 0
  attach()                                --fail--> Error + 1
  for step in block:                      --fail--> rollback_all(); Error + 1
    exec_step(step)
  script_enable(pid, path, state)         --持久化--> 失败则回滚
  print summary
  return 0
```

## 3. 功能点:script disable(执行 DISABLE,幂等)

### 3.1 功能分析

- 输入:脚本文件路径(经 `-p` attach)。
- 执行:
  1. 解析脚本 → DISABLE 步骤(无 DISABLE → 退出 2)。
  2. 幂等检查:`script_is_enabled` → 未启用 → 输出 `already disabled` 退出 0。
  3. 逆序执行步骤:unregistersymbol → hook 恢复(用保存的原始字节)→ dealloc(释放)。
  4. 全部成功 → 删除脚本记录。
- 输出:`OK` + 摘要(恢复目标地址、释放字节数)。
- 错误路径:未 attach → 退出 1;hook 恢复失败 → 退出 1(记录保留可重试)。
- 退出码:0 / 1 / 2。

### 3.2 功能流程

```
cmd_script disable:
  steps = parse_script(path)              --fail--> Error + 2
  block = steps[DISABLE]                  --无--> Error + 2
  if !script_enabled(pid, path): print "already disabled"; return 0
  attach()                                --fail--> Error + 1
  for step in block (reversed):           --fail--> Error + 1 (keep record)
    exec_step(step)
  script_disable(pid, path)               --持久化--> Error + 1
  print OK
  return 0
```

## 4. 功能点:script status(脚本/hook 状态)

### 4.1 功能分析

- 输入:无(经 `-p` attach)。
- 执行:读取脚本记录 → 输出状态表(脚本路径、hook 目标、分配地址、启用时间)。
- 输出:纯 ASCII 表;无记录输出空表头。
- 错误路径:未 attach → 退出 1。
- 退出码:0 / 1。

### 4.2 功能流程

```
cmd_script status:
  attach()                                --fail--> Error + 1
  list = script_list(pid)
  print_script_status(list)
  return 0
```

## 5. 功能点:AA 关键字执行(步骤执行器)

### 5.1 功能分析

| 关键字 | 语义 | 底层能力 |
|--------|------|----------|
| `alloc(name,size[,near])` | 分配远程内存,符号绑定 | 静态库 remote_alloc(带符号) |
| 裸汇编行 | 带 label 汇编后写入当前目标 | 静态库 asm_assemble_with_labels(写入地址) |
| `db <hex>` | 原始字节写入当前目标 | 静态库 memory_write |
| `"module"+offset:` | hook 目标:读原字节 → 改写 jmp → 保存 | 静态库 hook_set |
| `createThread(name)` | 在符号地址创建远程线程执行 | 静态库 thread_create_at |
| `dealloc(name)` | 释放符号内存 | 静态库 remote_free(带符号) |
| `label(name)` / `registersymbol` / `unregistersymbol` | 符号表操作(脚本内) | 静态库符号表 |

### 5.2 功能流程

```
exec_step(step, ctx):
  alloc:    addr = remote_alloc(size, near); ctx.symbols[name]=addr; print
  asm:      bytes = asm_with_labels(text, ctx.symbols); write(ctx.target, bytes)
  db:       write(ctx.target, hex_bytes)
  hook:     orig = read(target); patch = jmp_to(ctx.symbols[target_label]); write(target, patch); save_orig
  createThread: tid = thread_create_at(ctx.symbols[name]); print
  dealloc:  remote_free(ctx.symbols[name]); print
```
