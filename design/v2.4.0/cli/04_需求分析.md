# CLI - 需求分析(修改模式:需求变更文档,v2.4.0)

> 引用:v2.3.0/cli/04_需求分析.md 既有需求。本版本输出需求变更,逐条列出改动点。
> 输入:01_想法收集(想法)+ 用户设计决策确认(独立 check 命令 / 失败统一退出 2 / 不 attach)。

## 1. 已确认的设计决策(想法收集阶段的开放问题)

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 命令形式 | **`script check <file>`**:只检查不执行,可用于 CI/编辑器校验 |
| 2 | attach 依赖 | **不 attach**:check 为纯本地操作(读文件 + 解析 + 静态校验 + 汇编预检),不依赖 -p,无目标进程副作用 |
| 3 | 检查范围 | 三层:①文件读取 ②AA 语法解析(aa_parse_text,复用) ③执行前静态校验(hook 块结构)+ 汇编预检(占位地址调用 asm_assemble_labels) |
| 4 | 模块加载校验 | **不做**:模块加载依赖 attach,check 不 attach 无法判定,留到 run 时校验(不暗示 check 能验证模块加载) |
| 5 | 失败退出码 | **统一 2**(输入/脚本问题),与 run 的执行错误 1 区分开;成功输出 `OK` + 统计,退出 0 |

## 2. 脚本语法(引用 v2.3.0,不变)

语法与关键字完全沿用 v2.3.0 定义(alloc/label/registersymbol/unregistersymbol/
createThread/dealloc/db/`[ENABLE]`/`[DISABLE]`/裸汇编行/`"module"+offset:`),
本版本不修改语法,只新增「不执行」的检查入口。见 v2.3.0/cli/04_需求分析.md §2。

## 3. 需求变更清单

| # | 改动点 | 新增/修改/删除 | 影响命令组/功能 |
|---|--------|----------------|-----------------|
| 1 | `script check <file>`:只检查脚本(读文件 → 语法解析 → 结构校验 → 汇编预检),不 attach、不执行、无目标副作用 | 新增 | script |
| 2 | 汇编预检:脚本内全部裸汇编行按「当前写入目标」分组,用占位地址调用静态库 asm_assemble_labels,捕获未知指令/非法操作数/未定义 hook 跳转 label | 新增 | script |
| 3 | hook 块结构静态校验:ENABLE 块内 hook 目标后必须为 `jmp <label>` 且 label 已定义(alloc 符号或脚本内 label) | 新增 | script |
| 4 | 失败退出码统一 2(文件/语法/结构/汇编问题均为输入问题),成功 0 | 新增 | script |
| 5 | 既有 script run/disable/status 与全部命令保留(兼容) | 不变 | 全局 |
| 6 | 版本号 2.4.0(help/version/CMake/测试断言) | 修改 | 全局 |

## 4. 无交互与纯 ASCII 约束复核

- check 无阻塞输入等待;文件读取为 I/O;执行完立即退出;一次调用一个操作。
- 所有输出纯 ASCII;错误消息统一 `Error:` 前缀。
- check 无资源分配/写入/线程/句柄操作 → 无配对资源问题;不产生任何目标副作用。
- 新增需求点满足无交互与纯 ASCII 约束。

## 5. 能力边界声明(声明支持 / 不支持)

- **支持**:`script check <file>` 对任意脚本文件做三层校验;脚本语法范围与 v2.3.0 相同;
  汇编预检覆盖脚本内全部裸汇编指令;hook 块结构静态校验(jmp label 必须已定义)。
- **不支持**(文档不暗示支持):
  - 模块加载校验(`"module"+offset` 引用的模块是否已加载)→ 需 attach,check 不检查,
    由 run 时校验(NotFound 退出 1)。
  - `alloc` near 表达式的模块加载校验 → 同上,check 仅校验表达式语法。
  - 执行期动态错误(分配失败/写失败/线程创建失败)→ 不属于「语法」范畴,check 无法预知。
- check 与 run 的检查差异明确:**check = 静态可判定问题(退出 2);run = 动态执行问题(退出 1)**。
