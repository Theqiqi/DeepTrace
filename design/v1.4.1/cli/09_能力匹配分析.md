# CLI - 静态库能力匹配(修改模式)

## 1. 静态库存在性匹配

- 静态库存在:deeptrace(公共头 `deeptrace.h`,库产物 `deeptrace/out/lib/<配置>/deeptrace.lib`)。
- 本版本改动不涉及任何进程/内存/扫描能力的新增,继续「API 能力覆盖性匹配」。

## 2. API 能力覆盖性匹配

CLI 能力需求(08 文档)逐项对照:

| 能力需求 | 提供方 | 覆盖 |
|----------|--------|------|
| 类型值解析/校验/转换(标准库数据变换) | CLI 接口调用层(C/C++ 标准库) | 无需静态库 |
| 字节 → 单行 hex 输出 | CLI 打印层 `print_bytes`(既有) | 无需静态库 |
| 无子动作命令解析 | CLI 命令层 parser(既有扩展) | 无需静态库 |
| 扫描(convert 输出的消费方) | `deeptrace::pattern_scan`(既有公共 API,零改动) | 沿用 |

### 匹配结论

- **静态库能力需求:无新增**。`convert` 是纯数据变换(输入格式化能力),
  与 CLI 既有的 `hex_bytes`/`to_addr` 等辅助同级,属 CLI 自身的参数/输出格式化职责,
  不属于进程内存操作能力,故不构成静态库能力缺口,不触发静态库流程。
- 扫描功能保持 `resolve scan <pattern>` → `pattern_scan` 的原调用链,零改动。
- 不满足「绝对不允许在 CLI 中自行实现缺失功能」的前提:该条款针对的是
  **进程内存操作能力**(应由静态库提供);数据格式转换不在静态库能力清单内,
  CLI 用标准库实现属于既定边界(与 asm 输出格式化、地址格式化同理)。
