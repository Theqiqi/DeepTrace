# CLI - 想法收集(修改模式)

## 1. 输入想法

**功能添加**:CLI 需要新增"不同类型数据 → 十六进制字节"的转换能力。用户输入
不同类型的数据值(整数/浮点/字符串/hex),CLI 输出对应的十六进制字节(小端序),
输出格式与 `resolve scan` 的 pattern 输入兼容——即转换结果可直接作为扫描模式使用,
匹配 scan 的搜索。

例如:

- `convert dword 100` → 输出 `64 00 00 00`(100 的 dword 小端字节)
- `convert float 3.14` → 输出 IEEE754 单精度小端字节
- `convert string hello` → 输出 ASCII 字节 `68 65 6C 6C 6F`
- `convert hex DEADBEEF` → 输出 `DE AD BE EF`
- 输出可直接给 `resolve scan` 使用:`resolve scan "64 00 00 00"` 扫描该字节模式

## 2. 设计修正说明(相对 v1.4.0)

- **v1.4.0 的设计错误**:把类型值转换直接做进了 `resolve scan`(增加可选 type 参数),
  改变了既有扫描命令的签名与行为,属于"改了扫描功能"而不是"新增转换功能"。
- **本版本修正**:撤销对 `resolve scan` 的全部改动,恢复 v1.3.0 纯 AOB pattern 行为;
  转换能力实现为**独立命令 `convert`**(无子动作),类型在前、数据在后:
  `convert <type> <value>`。
- 转换命令为纯数据变换,**不需要目标进程**,无需 `-p`,不涉及 attach/detach。

## 3. 期望

- 新增独立命令组 `convert`:参数为 `<type> <value>`(类型在前),type 取值
  `byte|word|dword|qword|float|double|string|hex`
- 转换逻辑放在 CLI 接口调用层,只用 C/C++ 标准库实现(不调 OS API,不新增静态库能力)
- 全部输出仍为纯 ASCII;无交互约束不得被破坏(一次调用一个操作,执行完立即退出)
- 新增参数校验(类型枚举 + 按类型的值校验),错误消息纯 ASCII、退出码语义不变
  (0 成功 / 1 业务错误 / 2 用法错误;convert 全部错误为用法错误退出码 2)
- 静态库 deeptrace 不做任何改动:扫描能力完全复用既有 `pattern_scan` 公共 API

## 4. 涉及范围

- 命令层:`commands.cpp`(命令表/帮助)、`parser.cpp`(参数校验 + 无子动作命令解析)
- 接口调用层:`cmd.h`、`executor.cpp`(typed_bytes 转换辅助 + 分派)、新增 `cmd_convert.cpp`
- 打印层:复用既有 `print_bytes` 单行 hex 输出;仅版本号字符串更新
- 测试:parser / executor 单元测试、集成测试(convert 输出喂给真实 scan)、e2e 用例
