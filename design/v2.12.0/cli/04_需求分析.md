## 2. 需求说明

### 2.1 指针链搜索(新增功能点)

**动机**:游戏关键值(HP/MP)地址动态变化,需从值反推稳定指针链
(模块基址 + 偏移);CE 同款场景。v2.9.0 batch 消费链,v2.12.0 生产链。

**输入**:`resolve ptrscan <file.json>`;JSON 定义扫描配置:
```json
{ "version": 1,
  "target": "0x7FF62A1B2100",   // 目标值地址(必填)
  "module": "Game.exe",         // 锚定模块(可选;缺省 = 不锚定)
  "max_offset": 2048,           // 可选,默认 2048
  "max_level": 5,               // 可选,默认 5
  "max_results": 10000,         // 可选,默认 10000
  "threads": 0,                 // 可选,0 = 自动(hardware_concurrency)
  "rescan": null                // 可选:{"target": "0x..."} 触发重扫过滤
}
```

**处理**:
- 无 rescan:调 `pointer_map_snapshot` 反向反推 → 打印链列表。
- 有 rescan:先快照得 base 链,再调 `pointer_map_rescan(base, new_target)`
  交集过滤 → 打印过滤后链列表。
- 输出每条链为 `module+root_offset + off1 + off2 ...`(兼容 batch 定位器
  的 `module/base/offsets` 字段)。

**输出示例**:
```text
$ deeptrace_cli -p 1234 resolve ptrscan scan.json
Game.exe+01AF89C0 +38 +104 +8
Game.exe+01AF89C0 +38 +10C +8
...
(3 chains, 2 after rescan)
```

**无交互约束**:一次调用一操作、执行完立即退出;输出纯 ASCII;扫描是
单次同步调用(大范围可能慢,由 max_offset/max_results 控制)。

### 2.2 受影响既有功能点

- resolve base/scan 不变;mem batch(消费链)不变;搜索→验证闭环。

## 3. 能力边界(声明支持 / 不支持)

- 支持:JSON 配置快照/重扫;模块锚定;max_offset/max_level/max_results/
  threads 全参数;链输出兼容 batch。
- 不支持/错误:
  - JSON 非法 / version≠1 / target 缺失 → 用法错误退出 2。
  - 未 attach / 锚定模块未加载 → 业务错误退出 1。
  - 无结果 → `No chains found` 退出 0(非错误)。
  - 指针链保存/管理(文件即存储,打印列表,同 v2.9.0)。

## 4. 需求点设计

| 需求点 | 说明 |
|--------|------|
| R1 快照 | JSON → pointer_map_snapshot → 链列表打印 |
| R2 重扫 | JSON rescan 段 → 先快照再 rescan 过滤 → 打印 |
| R3 链格式 | module+root_off + off1 + off2...(兼容 batch) |
| R4 配置错误 | JSON/version/target 非法 → 退出 2 |
| R5 业务错误 | 未 attach / 模块未加载 → 退出 1 |
