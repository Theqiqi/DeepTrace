## 2. API 能力覆盖性匹配

| CLI 能力需求 | 提供方 | 覆盖 |
|--------------|--------|------|
| 文本/二进制文件读写、hex 解析、source 判定 | CLI(标准库自实现) | 无需静态库 |
| 汇编代码 → 机器码(asm file / exec .asm) | 既有 `asm_assemble(code, bytes, text)` | 覆盖 |
| 注入记录持久化与输出 | 既有 store(save/load_injects)+ print_inject | 覆盖 |
| 分配 + 写入 + 立即执行(inject/injectat/injectfile) | 既有 `shellcode_inject`/`shellcode_inject_at` | 覆盖 |
| **分配 + 写入,不执行(alloc)** | **无对应 API** | **缺失** |
| **对已记录地址创建远程线程触发一次(run)** | **无对应 API** | **缺失** |
| **释放已分配内存 + 删除记录(free)** | **无对应 API** | **缺失** |

### 匹配结论

- 缺失能力 3 项:`shellcode_alloc` / `shellcode_run` / `shellcode_free`。
- 其余能力全部覆盖;静态库流程被触发(见 09_静态库流程交接记录)。

## 3. 缺失能力分析(静态库需求)

> 详见 design/v2.2.0/pmem/ 静态库需求变更文档(与交接记录一并交付静态库流程)。

| 缺失能力 | 期望公共 API | 输入 → 输出 | 异常要求 | 验收标准 |
|----------|--------------|-------------|----------|----------|
| 只分配+写入不执行 | `shellcode_alloc(bytes, out)` | 字节 → InjectInfo(地址/tid=0/running=no),记录持久化 | NotAttached/InvalidArg/分配失败(无残留) | 分配内存可 mem 读取到写入字节,无线程产生;记录可 status 查见 |
| 触发已记录地址一次 | `shellcode_run(addr, out)` | 地址 → InjectInfo(新 TID/running=yes),记录更新 | NotAttached/NotFound/建线程失败 | 每次调用创建一条新远程线程并执行;记录 TID 更新 |
| 释放已记录地址 | `shellcode_free(addr)` | 地址 → Ok | NotAttached/NotFound/释放失败 | 远程内存释放,记录删除;再次 run/free 该地址 → NotFound |
