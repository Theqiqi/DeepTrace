# CLI - 能力需求列表(修改模式,v2.2.0)

> 只回答「CLI 需要做什么」,不回答「用什么做」。聚焦改动点新增能力需求。

## 1. 改动点能力需求

| # | 能力需求 | 说明 |
|---|----------|------|
| 1 | 读文本文件(.asm/.s) | CLI 标准库(std::ifstream) |
| 2 | 读二进制文件(.bin) | CLI 标准库(std::ifstream binary) |
| 3 | 写二进制文件(.bin,asm --out / hex2bin) | CLI 标准库(std::ofstream binary) |
| 4 | hex 字符串 → 字节(hex2bin/alloc/exec 输入) | 复用既有 hex_bytes 辅助 |
| 5 | 汇编代码 → 机器码字节(asm file / exec 的 .asm 输入) | 复用既有 asm_assemble 公共 API |
| 6 | **分配 + 写入 shellcode,不执行,输出首地址**(alloc) | **缺失 → 静态库流程** |
| 7 | **对已记录地址创建远程线程触发一次**(run) | **缺失 → 静态库流程** |
| 8 | **释放已分配内存 + 删除记录**(free) | **缺失 → 静态库流程** |
| 9 | 注入记录持久化(跨调用衔接 alloc/run/free) | 既有 records 存储(save_injects/load_injects) |
| 10 | 注入记录输出格式(地址/TID/running) | 复用 print_inject/print_injects |
| 11 | source 自动判定(hex / .bin / .asm) | CLI 自实现(标准库,确定性规则) |

## 2. 能力覆盖判断

- 1/2/3/4/11:CLI 标准库自实现(与既有 hex_bytes/convert 辅助同级)。
- 5:既有 `asm_assemble` 公共 API 覆盖,直接复用。
- 9/10:既有存储与打印层覆盖,直接复用。
- 6/7/8:静态库**无对应公共 API**(仅有 shellcode_inject 一体「写入+立即执行」,
  无「只写入不执行」「单独触发」「释放清理」)→ **缺失能力 3 项**,
  进入静态库流程新增 `shellcode_alloc`/`shellcode_run`/`shellcode_free`;
  静态库完成契约返回后重新匹配(见 09_能力匹配分析)。
