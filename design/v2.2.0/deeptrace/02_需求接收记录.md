# deeptrace - 跨流程需求接收记录(design/v2.2.0/deeptrace/02_需求接收记录.md)

> 关联交接记录:design/v2.2.0/cli/09_静态库流程交接记录.md(CLI v2.2.0 发起)。

## 1. 接收清单(逐项)

### M1:只分配+写入,不执行

| 项 | 内容 |
|----|------|
| 缺失能力 | 分配 + 写入 shellcode,不执行,输出分配首地址 |
| 期望公共 API | `Result shellcode_alloc(const std::vector<uint8_t>& bytes, InjectInfo& out)` |
| 输入 | 机器码字节(非空) |
| 输出 | InjectInfo{kind="shellcode", remote_base=首地址, thread_id=0, running=false, size} |
| 异常要求 | 未 attach → NotAttached;空字节 → InvalidArg;分配失败 → 分配错误;写入失败 → 释放后返回错误(无残留) |
| 验收标准 | ①不产生远程线程;②内存内容=写入字节(memory_read 验证);③记录可 status 查见(running=no);④失败路径无残留 |

### M2:触发已记录地址一次

| 项 | 内容 |
|----|------|
| 缺失能力 | 对已记录地址创建远程线程触发一次(可重复) |
| 期望公共 API | `Result shellcode_run(uintptr_t addr, InjectInfo& out)` |
| 输入 | 注入记录内地址(kind=shellcode) |
| 输出 | InjectInfo{kind="shellcode", remote_base=addr, thread_id=新建TID, running=true};记录更新 |
| 异常要求 | 未 attach → NotAttached;地址不在记录 → NotFound;建线程失败 → 错误(记录不变) |
| 验收标准 | ①每次调用创建一条新远程线程并执行;②可重复调用;③记录 TID 反映最近触发;④未记录地址 → NotFound |

### M3:释放已记录地址

| 项 | 内容 |
|----|------|
| 缺失能力 | 释放已分配内存 + 删除记录(痕迹清除) |
| 期望公共 API | `Result shellcode_free(uintptr_t addr)` |
| 输入 | 注入记录内地址(kind=shellcode) |
| 输出 | Result::Ok;记录删除 |
| 异常要求 | 未 attach → NotAttached;地址不在记录 → NotFound;释放失败 → 错误(记录保留) |
| 验收标准 | ①远程内存释放(VirtualFreeEx);②记录删除(再 run/free → NotFound);③可释放任一 shellcode 记录(alloc/inject/injectat/injectfile/exec 产生) |

## 2. 约束确认

- 使用真实底层能力:VirtualAllocEx/VirtualFreeEx/WriteProcessMemory/CreateRemoteThread
  (经既有基础设施 RemoteAlloc/RemoteFree/WriteRemoteMemory/CreateRemoteThreadEx),禁止模拟/硬编码/伪造。
- 分层:Service 层组装(记录查找/更新 + 基础设施调用);不新增基础设施。
- 既有公共 API 全部保持兼容;注入记录格式与存储(save_injects/load_injects)不变。
- 接收完成,进入需求分析。
