# deeptrace - 需求分析(修改模式,v2.2.0)

> 引用:v2.0.0/deeptrace 既有需求文档。本版本聚焦 shellcode 分阶段操作需求。

## 1. 需求描述

CLI「汇编代码注入并执行」需要静态库支持 shellcode 的**分阶段操作**:

1. **写入不执行(alloc)**:在目标进程分配可执行内存并写入机器码,返回首地址,
   不创建线程——CLI 先注入、后手动触发;
2. **单独触发(run)**:对已注入的地址创建远程线程执行一次,且可重复(复用触发);
3. **释放清理(free)**:释放已注入的内存并清除记录(痕迹清除)。

现有 `shellcode_inject`/`shellcode_inject_at` 为「写入+立即执行」一体,
无法表达上述分阶段语义,故新增 3 个公共 API(全部复用既有基础设施)。

## 2. 需求点

| # | 需求点 | 验收 |
|---|--------|------|
| 1 | `shellcode_alloc(bytes, out)` 公共 API:分配+写入,不执行,记录持久化 | 集成测试:无线程产生、内存可读回、status 可见、失败无残留 |
| 2 | `shellcode_run(addr, out)` 公共 API:记录内地址创建新远程线程,更新记录 TID | 集成测试:可重复触发、TID 更新、未记录地址 NotFound |
| 3 | `shellcode_free(addr)` 公共 API:记录内地址释放内存 + 删记录 | 集成测试:内存释放、记录删除、再操作 NotFound |
| 4 | 分层与兼容:Service 组装(记录查找/更新 + 基础设施),不新增基础设施 | 代码审查:复用 RemoteAlloc/RemoteFree/WriteRemoteMemory/CreateRemoteThreadEx;既有 API 不变 |

## 3. 无新三方依赖

纯 Windows API(VirtualAllocEx/VirtualFreeEx/WriteProcessMemory/CreateRemoteThread,
经既有基础设施封装),不新增依赖。
