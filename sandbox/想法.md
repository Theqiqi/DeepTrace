# 想法

## 想法记录

- 想把 deeptrace 基础设施层里直接调用的 Windows API(内存操作等)改成**函数指针**调用,先验证这种方式是否可行,再决定是否重构
- 覆盖的 API:内存类(ReadProcessMemory / WriteProcessMemory / VirtualAllocEx / VirtualFreeEx / VirtualQueryEx / VirtualProtectEx)、进程类(OpenProcess / CloseHandle)
- 动机:①调用点统一、便于替换/插桩(测试时注入假实现,不必真起目标进程);②为将来"换实现"留口子
- 疑问:函数指针表怎么组织、直接赋值绑定 vs GetProcAddress 动态解析哪个合适、调用结果是否与直接调用一致、x64 调用约定有无坑

## 验证思路(3 个文件)

- `winapi.h/cpp`:函数指针类型 typedef + `WindowsMemoryApi` 表 + 全局唯一实例 `g_winapi`(直接赋值绑定真实函数、静态初始化一次,不经 GetProcAddress)
- `memory.h/cpp`:memory 原子化接口(读/写/分配/释放),内部直接取 `g_winapi`
- `main.cpp`:只做两三个原子调用,验证 memory 层经函数指针表工作

不写模拟实现——验证点就是"memory 层经表调用真实 Win32"这一形态。

## 验证目标

1. `g_winapi` 直接赋值绑定 8 个函数指针(链接器正常解析导入,不经 GetProcAddress)
2. 全局唯一实例:main 与 memory 层直接取用,零实例化、零传表、零函数
3. 编译链接 + main 调用:alloc → write → read 读回一致 → free → close,退出码 0
