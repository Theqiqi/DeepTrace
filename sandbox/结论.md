# 结论

## 验证内容与环境

- 验证:开源反汇编库 Capstone(5.0.9)能否替代自研引擎——vcpkg 接入可行性 + 基础调用 + 能力覆盖
- 环境:Windows x64,MSVC 19.44(vcvars64),CMake + Ninja + CMakePresets(Debug /MDd),vcpkg manifest
- 验证程序:`sandbox_disasm.exe`,12 条字节序列(7 条自研引擎支持的基础指令 + 5 条自研引擎不支持的 SSE/SSE2/REP 指令),其中 10 条含文本断言、2 条仅打印(call/jmp)

## 检查点结果(对照验证清单)

| # | 检查点 | 结果 | 证据 |
|---|--------|------|------|
| 1 | vcpkg 能安装 capstone | ⚠️ 能装能链,但 port 默认残废 | capstone 5.0.9 安装并链接成功;但 CMakeCache 显示 `CAPSTONE_ARCHITECTURE_DEFAULT=OFF`、`CAPSTONE_X86_SUPPORT=OFF`/ARM/ARM64 全 OFF,只编译了 7 个核心文件、无任何架构后端 |
| 2 | 链接成功并运行 | ✅ | sandbox_disasm.exe 生成并运行;但 cs_open 对所有架构返回 CS_ERR_ARCH(arch_configs[].arch_init 全空) |
| 3 | 基础指令解码 | ✅ | mov/movabs/lea/add/jmp/call/syscall 全部正确(len 与文本断言通过) |
| 4 | 自研引擎不支持的指令 | ✅ | movups/pxor/cvtsi2sd/movdqu(SSE/SSE2)、rep movsb(REP 字符串)全部正确解码 |

最终:10/10 断言通过,退出码 0(自建 capstone + 仅 x86 后端路径)。

## 三态结论

- **能实现**:Capstone 反汇编能力完整可用,覆盖自研引擎的全部缺口(SSE/SSE2/AVX、REP 字符串指令等),基础调用 API 简单(cs_open → cs_disasm → 逐条 mnemonic/op_str/size)
- **缺条件才能实现(关键)**:vcpkg 的 capstone port 在此环境**默认把全部架构禁用**(portfile 显式传 `-DCAPSTONE_ARCHITECTURE_DEFAULT=OFF` 且未开启任何架构),开箱即用的 DLL 无法反汇编任何指令。**缺**:绕过手段——① 工程内 add_subdirectory 自建源码(已验证,仅 16 个编译单元);② 或查 port 的 feature 开启架构;③ 或 overlay port 修 portfile
- **无法实现/不现实**:无——capstone 本身无功能阻碍;vcpkg 接入的坑可绕过

## 探索过程记录(弯路也是结论)

1. 首次 cs_open 失败 → 打印错误码定位为 CS_ERR_ARCH
2. 多架构诊断:所有架构全失败 → 排除"仅 x86 被禁"
3. 发现安装的 capstone.dll 仅 22KB、.ninja_log 仅 7 个编译单元 → 怀疑残废构建
4. 读 vcpkg 构建的 cs.c 源码:CS_ERR_ARCH 即 `arch_configs[arch].arch_init` 为空 → 架构后端未编译
5. CMakeCache 实锤:全部 `CAPSTONE_*_SUPPORT=OFF` → vcpkg port 配置问题(非 capstone 本身问题)
6. 自建源码(仅 x86)后全绿 → 确认 capstone 本身完全可用

## 升级判定

- **评估结论**:替换自研引擎**技术上可行**,capstone 能力与 API 都满足;但**直接走 vcpkg manifest 会踩到 port 残废的坑**
- **建议**(供正式决策,不在本次 sandbox 范围内实施):
  - 若走 vcpkg:需先验证该 port 的 feature 方案(如 `capstone[x86]`)或 overlay port 修 portfile;本 sandbox 已验证的"工程内 add_subdirectory 自建源码"是可靠兜底
  - 若对接 pmem(情形一):新反汇编放 `src/infrastructure/disassembly/`,公开 API 不变(disasm_at/disasm_range),内部实现换 capstone;需再验证一次对接落位
  - 若保留自研引擎:必须按流程要求补齐"白名单=实现集"声明、完整性审查与全量测试(当前 15 个用例远未覆盖)
- 本 sandbox(情形二 独立探索)到此闭环;对接 pmem 的验证建议另起一次 sandbox(情形一)
